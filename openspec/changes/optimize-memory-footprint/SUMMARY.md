# BBHouse 内存优化修复状态

2026-09-21，接续 [审查报告](../../../doc/内存优化审查与高画质内存分析.md)。本文件更新为修复后的状态，旧版本的预期内存数字不再作为收益依据。

## 已实现

- 在线历史、动态、本地历史使用 GridView。页面回收沿用远端 `ExpiringPageLoader`（离开后按设置保留，默认 5 分钟，超时卸载并释放控制器浏览缓存）；本 change 原单活跃 Loader 方案已于 2026-09-23 变基时被取代，控制器侧状态记忆叠加其上。
- 动态池按首次追加顺序淘汰，与发布时间排序解耦；综合热门才应用热门池上限。三个无限列表的保留条目在头部裁剪后按身份恢复视口。
- 补齐流行/直播的搜索、分页和滚动恢复；在线历史等待模型布局后恢复；动态用稳定卡片身份及行内偏移恢复。非空但不足一屏的在线/动态投影支持有限续载。
- 番剧/稍后再看分页控件与数据页码一致；下载保存标签、搜索、页码和滚动，关于保存滚动；特别关注通过可写 QML 属性同步搜索及标签。
- SeasonCard 沿用 FluImage 的 DPR 2 解码上限。DPR≤2 没有额外解码收益，DPR>2 避免原无上限覆盖导致像素数增加。
- 新增真实 QML 销毁重建回归；修复或处理原四项测试失败，结果见交付文档。

## 收益与边界

虚拟化限制活动卡片数量，2000 条池限制对应条目数；二者不等于整个进程/控制器/驱动缓存都零内存。锚点被池淘汰时返回保留窗口起点，无法同时保证硬上限与无限保留所有已浏览条目。

尚未测得整个应用修复前后的统一内存收益，不承诺空闲或播放固定 MB 数字。Arc 140T 的真实杜比用例已单独测量，媒体管线依然存在较高资源成本；同内容弹幕复用及媒体诊断由独立 `reduce-player-memory-churn` change 记录。

用户 UI 手测和正式内存验收未完成，本 change 不归档。详见 [修复交付与手测](../../../doc/内存优化修复与杜比用例验证.md)。
