## MODIFIED Requirements

### Requirement: 云端数据源与只读性

在线历史页 MUST 以云端观看历史 cursor API 为数据源按需拉取条目并渲染为与本地历史一致的瀑布流卡片（列宽 300px、自适应列数、虚拟化网格、整体居中，渲染方式按 history-browser-ui 规格）；MUST NOT 将拉取到的数据写入本地数据库，MUST NOT 触发同步或影响本地缓存口径；页面 MUST NOT 显示分页栏。

#### Scenario: 进入页面拉取首页

- **WHEN** 用户切到"在线历史"页
- **THEN** 页面向云端请求第一页（30 条）并渲染卡片，本地数据库无任何写入

#### Scenario: 卡片视觉一致

- **WHEN** 同一条目分别出现在在线历史与本地历史页
- **THEN** 卡片元素与布局一致（封面/角标/标签/进度等，展示属性来自同一 ViewModel，渲染方式同为虚拟化网格）

### Requirement: 无限滚动加载

列表 MUST 以无限滚动方式续载：每页 30 条，滚动位置接近列表底部（最后三行高度内）时 MUST 自动请求下一页并追加渲染（当前搜索词下匹配的条目进入可见列表）；云端游标耗尽或返回空页时 MUST 停止续载并呈现本地化的"已到底"提示；连续两页出现重复条目（同 video_key）时 MUST 去重；游标与上一页相同（防死循环信号）时 MUST 视为到底。当前投影（搜索叠加）为空且未到底时 MUST 自动续载并链式推进（连续自动轮设上限、轮间短暂步进、不依赖滚动或布局事件），直到出现匹配、到底或达上限；达上限仍为空 MUST 呈现本地化"未找到匹配"提示，用户手势（滚动、提交搜索、刷新）MUST 可从保留的游标进度恢复续载。已加载条目池 SHALL 设置内存安全上限（远高于单次正常浏览可达到的数量）：超出上限时 SHALL 丢弃最早追加的条目，该上限不得在正常浏览场景下触发，且不改变到底判定、去重、搜索投影与刷新的既有行为。

#### Scenario: 滚动触发续载

- **WHEN** 用户滚动至距列表底部最后三行范围内
- **THEN** 自动请求下一页并追加卡片，滚动无需用户再次操作

#### Scenario: 云端到底

- **WHEN** 游标耗尽或返回空页后用户继续滚动
- **THEN** 不再发起新请求，列表底部显示本地化到底提示

#### Scenario: 重复条目去重

- **WHEN** 续载返回的条目中存在与已渲染条目相同的 video_key
- **THEN** 该条目不重复渲染

#### Scenario: 空投影自动续拉

- **WHEN** 用户提交了在已加载条目中无匹配的搜索词且云端未到底
- **THEN** 页面不依赖滚动或布局事件，自动连续续载直至出现匹配、到底或达连续自动轮上限（达上限呈现"未找到匹配"提示，重新提交搜索或刷新可恢复）

#### Scenario: 超长会话池上限

- **WHEN** 单次会话内持续滚动续载至条目池达到内存安全上限
- **THEN** 最早追加的条目被丢弃以维持上限，用户仍可继续向下滚动加载更新条目，到底判定、去重与当前搜索投影不受影响
