## MODIFIED Requirements

### Requirement: 数据源与只读卡片瀑布流

动态页 MUST 通过 bilibili-api-client 提供的动态流列表端点拉取条目，以瀑布流（虚拟化网格，渲染方式按 history-browser-ui 规格：列宽固定、自适应列数、统一行高取实测最大卡片高度、整体居中）呈现只读卡片；卡片 MUST 展示封面图、标题或文字摘要、作者名、发布时间戳、时长（视频类）；每张卡片对应一条动态，卡片数据 MUST 来自端点解析结果，MUST NOT 落库。瀑布流 MUST 虚拟化渲染：仅视口内及邻近缓冲区域的卡片保持为活动渲染项，离屏卡片 MUST 被回收并在重新进入视口时以相同内容重建；虚拟化 MUST NOT 破坏"分区补查增量呈现"等既有局部更新契约——分区补查逐条完成时 MUST 仅更新对应行数据，MUST NOT 因虚拟化机制额外销毁重建仍在投影中的卡片。

#### Scenario: 首次进入动态页

- **WHEN** 应用启动默认进入动态页或用户点击"动态"菜单项
- **THEN** 页面请求动态流首页并以瀑布流呈现卡片（封面/标题/作者名/发布时间/时长文本齐全且来自端点数据），无本地持久化读写发生

#### Scenario: 卡片展示完整

- **WHEN** 动态流中包含视频、专栏、图文、转发等不同类型动态
- **THEN** 每张卡片按类型呈现对应字段（视频类展示时长与 av 号可见标志、图文类展示首图与文字摘要、转发类展示原动态标题与封面），所有卡片封面图均正常加载并显示

#### Scenario: 瀑布流非虚拟化

- **WHEN** 本变更之前的实现曾要求"全部动态卡片都已渲染、无卡片销毁与重用"
- **THEN** 该行为已被本次引入的虚拟化渲染取代，不再适用；替代行为见"瀑布流虚拟化滚动"场景

#### Scenario: 瀑布流虚拟化滚动

- **WHEN** 用户滚动动态页且已加载数百条动态
- **THEN** 仅视口与缓冲区内的卡片为活动渲染项，滚动无白块闪现，滚回已浏览区域时卡片以相同内容正确重建

### Requirement: 无限滚动与稀疏筛选续拉

用户滚动至列表末尾（距底部最后三行）时页面 MUST 自动续拉下一页；续拉 MUST 携带上一响应返回的 offset，MUST 将新条目追加进已加载池（当前分类筛选与搜索叠加下匹配的条目进入可见列表），MUST 尊重端点返回的"无更多"终止信号。当前投影（分类筛选∩搜索）不足一屏时页面 MUST 自动续拉直到投影填满一屏、遇终止信号或达到连续自动轮上限；**投影为空且未遇终止信号时同样 MUST 自动续拉**（空列表无法滚动，续拉推进 MUST NOT 依赖滚动或布局事件）。连续自动轮 MUST 设上限：达到上限时投影仍为空 MUST 呈现本地化"未找到匹配"提示并停止自动续拉；此后的用户手势（可滚动时的滚动、切换筛选、提交搜索、刷新）MUST 可恢复续拉（续载进度保留，从上次 offset 继续）。自动续拉 MUST 避免连打（前一请求未完成前不发起新请求，连续自动轮之间有短暂步进）。滚动到真正的数据底部（已遇终止信号且无更多可拉）时 MUST 在列表末尾展示"已到底"提示。已加载池 SHALL 设置内存安全上限（远高于单次正常浏览可达到的数量）：超出上限时 SHALL 丢弃最早追加的条目及其去重分组记录，该上限不得在正常浏览场景下触发，且不改变到底判定、去重合并、分类/分区/搜索投影与刷新的既有行为。

#### Scenario: 滚动续载

- **WHEN** 用户滚动动态页至距底部最后三行
- **THEN** 页面自动发起下一页请求并将新卡片追加到列表末尾，滚动无明显停顿

#### Scenario: 稀疏筛选自动续拉

- **WHEN** 用户选中"专栏"筛选且首页仅返回 2 条专栏动态（其余为视频），筛选后不足一屏
- **THEN** 页面自动续拉下一页直到专栏类卡片填满一屏或遇终止信号，用户无需手动滚动

#### Scenario: 空投影自动续拉

- **WHEN** 用户切到一个当前投影为空的筛选档（或提交了无匹配的搜索词）且动态流未遇终止信号
- **THEN** 页面不依赖滚动或布局事件，自动连续续拉轮直至出现匹配条目、遇终止信号或达连续自动轮上限

#### Scenario: 未找到匹配提示

- **WHEN** 连续自动轮达到上限时投影仍为空且未遇终止信号
- **THEN** 列表末尾呈现本地化"未找到匹配"提示并停止自动续拉；用户切换筛选、重新提交搜索或刷新后可从保留的续载进度恢复续拉

#### Scenario: 续拉避免连打

- **WHEN** 稀疏筛选或空投影自动续拉过程中前一请求尚未完成
- **THEN** 页面不发起第二个并行请求，等待前一请求完成后再判断是否需要继续续拉；连续自动轮之间保持短暂步进

#### Scenario: 到底提示

- **WHEN** 用户滚动至真正的数据底部（端点返回"无更多"信号）
- **THEN** 列表末尾展示"已到底"提示（zh-CN 如"已经到底了"，en-US 如"End of feed"），无更多续拉发生

#### Scenario: 超长会话池上限

- **WHEN** 单次会话内持续滚动续拉至已加载池达到内存安全上限
- **THEN** 最早追加的条目及其去重分组记录被丢弃以维持上限，用户仍可继续向下滚动加载更新条目，到底判定、分类/搜索投影不受影响
