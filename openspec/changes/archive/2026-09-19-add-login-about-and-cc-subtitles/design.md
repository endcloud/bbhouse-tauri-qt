## Context

项目以 AppPaths 定位 Cookie，后台和页面控制器在请求时读取凭据。FluentUI 自带二维码生成组件；PlayerApi 已有字幕元数据端点，下载模块已有 JSON 字幕处理。本地媒体与在线媒体共用标准 PlayerWindow/PlayerControls。

## Decisions

- 登录使用独立控制器、初始化窗口和页面，通过现有 Cookie 读取路径原子写入 bilibili.cookie.txt；经 nav 校验成功前不替换当前凭据。导入后进入主窗口；稍后登录进入下载管理以使用本地媒体。无凭据时先显示初始化页面，避免默认动态页先发失败请求。重新登录复用相同页面。
- 用户扫码测试反馈后，暂时移除登录页二维码组件和触发按钮、设置扫码提示，保留控制器实现供后续修复；当前页面不触发扫码请求。导入支持文件与粘贴，校验后保存，避免暴露原文。登录页内嵌可展开的 Cookie-Editor Header String 导出步骤及 Edge 商店链接，并提供完整 Markdown 帮助。
- 关于页遵循冻结 56px 标题带及 24px 页面边距；依赖逐项可点击并显示介绍，保留许可说明与可复制版本。
- 字幕信息独立于视频取流加载，失败不阻断播放；不按 AI 标记过滤。选择及异步结果归当前播放会话，切片清理，禁用 mpv 自动选择字幕。
- CMake 的项目版本作为应用版本来源，macOS 打包从项目声明读取，避免版本漂移。

## Risks / Trade-offs

- B 站扫码及字幕受服务端账号权限与接口状态约束，使用离线 fixture 和非交互回归验证，真实导入/视频效果由用户手测；扫码暂不纳入当前验收。
- 保留已有微软图标字体授权边界，不在本次扩大许可清理范围。

## 帮助分发与导航顺序调整

- `doc/Cookie导入帮助.md` 直接通过 `qt_add_resources` 嵌入 `:/help/Cookie导入帮助.md`，避免维护资源副本或额外的打包复制步骤。
- 导航底部从上到下调整为“设置”、“关于”；按页面 key 路由，页面缓存与内容宿主索引保持对应。
