## Context

旧包 `af874cc` 首帧后出现 `0xc0000005`，音视频共同路径需结合调用栈定位。libmpv 源文件、构建目录和包内文件哈希相同，未被 strip。原部署冒烟为 PCM/vo=null/hwdec=no。

## Decisions

- 原生隐藏 HWND 对照定位到 SMTC：`MediaAbi` 的匿名命名空间内部链接触发 GCC `-O3` 将外部 COM 虚调用去虚化为 pure-virtual。接口移到具名外部命名空间，具体实现仍私有；不降低优化或改变 mpv 硬解。
- 优先用非交互本地合成视频与原生组件回归获取证据，不猜测更换 mpv 或删除运行依赖。
- 保留视频渲染就绪握手、配置和用户数据库隔离。
- 在裁剪后包内执行视频路径，失败阻止发布；旧发布目录不覆盖。
- 原生媒体回归通过读取实际 COM 状态和元数据判断成功，失败不能静默降级成通过；同一验证函数用于 CTest 与最终 EXE。

## Risks / Trade-offs

图形与系统媒体行为依赖 Windows 原生环境；自动检查不代替用户对在线业务和窗口交互的验收。最终根因及验证结果在交付文档记录。
