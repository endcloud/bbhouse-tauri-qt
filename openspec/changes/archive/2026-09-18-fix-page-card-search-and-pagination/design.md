## Context

当前 Qt 实现的窗口搜索使用 FluTextBox。该控件拦截 Enter 并发出自定义 `commit` 信号，不能依赖普通 TextField 的 `accepted` 接线；标题栏又曾把一个全局词绑定给各页。专栏空态位于滚动内容内，当内容高度为零或滚动残留时，中心锚点不再代表可见区域。稍后再看接口一次返回快照，分页应发生在客户端。

## Goals / Non-Goals

本次目标是修复用户指定的空态、卡片入口、搜索提交与作用域，并补齐稍后再看的本地分页。实现保持既有 API、播放解析、会话单实例、封面预览和非视频链接行为。不新增服务端搜索或分页，不迁移本地记录页和计划任务，不开展旧 WinUI 规格的整体重写。

## Decisions

1. 空态放在滚动容器的同级视口覆盖层，锚定实际可见内容区而非内容高度。提示按可用宽度扣除边距后换行，避免长错误、无匹配与专栏提示越界；现有非空列表与加载行为保持。
2. 可播放视频的非封面左键复用原 `playInNewWindow()` 播放入口，仍由统一播放管线决定普通稿件或 PGC 定位及权益处理。共享右键菜单删除播放项而保留打开链接；失效视频不发起播放；非视频仍打开浏览器。SeasonCard 表示番剧或合集实体，既有左键播放与右键详情不属于待删除的视频右键播放项。
3. 主窗口仅保存当前编辑框草稿，页面自身的 `searchQuery` 是已提交值。macOS 与 Windows 标题栏均通过 FluTextBox `onCommit` 与失焦调用同一提交函数；输入、删除、清空按钮仅修改草稿。页面切换时先向旧页面提交草稿，再更新活动页面并恢复其词；隐藏搜索框的设置页不持有搜索状态。各页的既有分类、分段、续载边界不变。
4. 稍后再看控制器持有服务端全量池，先做不区分大小写的标题/UP 主子串筛选，再切出每页 30 条。搜索词实际变化才回到第一页；重复提交同一词不重置页码。普通翻页只调整本地投影并回到当前页顶部。刷新成功替换池并将原页码钳制到有效范围；刷新失败保留池、搜索词和页码。导航缓存保留这些状态。

## Specification Conflicts

- 原 `watchlater-ui` 明确禁止翻页栏，与本次用户需求冲突：以完整 MODIFIED 块替换为“接口仍全量、展示本地分页”，同步搜索、刷新及缓存条款，避免把显示分页误写成接口分页。
- 原搜索“跨页保持”措辞可被解释成全局共享词：明确为每页独立保存；导航先提交旧页，避免迟到的失焦事件污染新页。
- 原播放入口与多个页面条款要求左键浏览器、右键播放：本 change 完整修订这些直接受影响的 requirement，并将共享播放入口 requirement 重命名；播放器其他 requirement 中只有触发动作随新入口替换，保留其余规则与场景，不将历史未实现能力标成已完成。
- 当前 OpenSpec 校验要求 MODIFIED 块保留原 Scenario 标题，因此少数标题仍带“右键”等历史字样；其 WHEN/THEN 已明确改为左键起播或删除右键项，标题只保留作校验身份，不代表旧行为继续有效。
- `local-records-ui` 仍为未迁移目标，尚无页面接线；该旧规格的右键播放与浏览器描述作为后续迁移时应对齐的遗留差异记录，本次不通过修改其迁移任务冒充功能已实现。旧 WinUI/XAML、预解析、内核重建等不相关差异继续由既有积压审计文档跟踪。

## Risks / Trade-offs

搜索失焦与导航事件可能连续到达，需以旧活动页对象明确提交归属，并避免恢复目标词期间再次提交。客户端分页减少当前页卡片数量，但接口仍下载完整快照；本次不改变服务端负载。空态视觉位置和平台焦点行为仍需用户在 macOS/Windows 手测；代理负责离线测试、构建、静态审查与严格规格验证。

## Validation Strategy

离屏信号回归验证搜索草稿、提交、清空与页面隔离，静态核对稍后再看全量筛选、分页边界、刷新钳制和失败保留；静态核对两套搜索控件提交事件、页面独立词、全部共享视频卡片入口与空态锚点。构建主程序及测试目标，运行 CTest 和 OpenSpec 严格验证。手测覆盖专栏空态、长提示、Enter/失焦/清空/切页、各类视频与非视频卡片以及稍后再看多页搜索刷新。
