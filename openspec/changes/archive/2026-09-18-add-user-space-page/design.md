## Context

现有特别关注页具备三档内容与分页；MainWindow 使用缓存 Loader 的 StackLayout，原规格禁止返回按钮，需要将限制明确收窄到标题栏。参考图为设计依据而非逐像素复制。

## Goals / Non-Goals

**Goals:** 应用内浏览 UP 空间；内容区资料头、卡片框与主题一致；保留来源状态；复用已有端点及内容行为。
**Non-Goals:** 云端关注关系写入、完整社交主页、动态 feed 全量拉取、替代现有特别关注头像管理。

## Decisions

- 用主窗口信号转发卡片作者点击，以独立的二级空间 Loader 覆盖内容宿主；来源 Loader 保持常驻。空间同一 UP 不重复入栈，返回关闭二级展示；导航菜单切换退出二级页。
- 为空间新增独立 UserSpaceController，复用 SpecialFollowController 的三档 API；特别关注全局实例仅处理本地关注成员操作，不能被空间浏览修改当前 UP。
- 将特别关注页面的控制器参数化，在空间模式隐藏其标题与头像管理条，使用空间资料头和容器内页签。两种模式共用分页、合集展开、专栏与播放。
- UID 用 qint64/字符串或 QML double；缺失或无效标识保持非链接，不能根据昵称猜测 UID。
- 用户资料从已记录的用户名片 API 获取，失败保留入口提供的昵称/头像并允许重试。旧 UP 的晚返回不得污染当前空间。
- “设为特别关注”仅操作本地快照，等待本地装载完成后合并，原子写入且立即通知特别关注页。
- 搜索遵循 Enter/失焦提交；空间页有独立 searchQuery。播放全部使用当前页筛选后列表，不隐式下载作者全部历史投稿。

## Risks / Trade-offs

接口可能触发登录/风控；界面必须区分失败与真实空态。异步切 UP 或修改筛选要补拉最新请求并丢弃旧条件结果。宽窗口卡片可多列，窄窗口头部折行，避免按钮覆盖昵称。

## Migration Plan

先归档已验收系统媒体与头像缓存 change，再独立开发本 change。构建、离线回归、无头装载通过后提交，由用户手测验收。

## Open Questions

播放全部默认当前页筛选结果；若用户另指定全量再调整范围。
