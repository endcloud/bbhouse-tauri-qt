# local-records-ui Specification

## Purpose
定义"本地记录"页面的 UI 行为契约：待播/历史双分段与纯客户端切换、待播本地持久化与跨页"添加到待播"入口、待播卡片移除角标、播放全部与清空二次确认、播放窗口关闭归档（排除剧集模式）、历史视图概要与恢复播放（归档次数 badge 与 tooltip）、分段作用域搜索与帧缓存状态保持。

## Requirements

### Requirement: 待播本地持久化数据源

本地待播列表 MUST 持久化于应用本地存储，跨会话保留；MUST NOT 依赖网络或登录态，与云端稍后再看列表互不同步、互不影响。每个条目 MUST 保存足以离线重建卡片显示与播放窗口起播的字段快照（含 PGC 条目的原始定位信息）。列表 MUST 以 VideoKey 去重：对已存在条目的重复添加 MUST 为幂等无操作（不产生重复条目、不改变既有顺序）。新添加的条目 MUST 置于列表最前（最新在前）。持久化读写 MUST 容错：存储损坏或不可读时 MUST 回退为空列表且 MUST NOT 崩溃，后续写入正常生效。

#### Scenario: 添加后跨会话保留

- **WHEN** 用户在某卡片页右键"添加到待播"后重启应用并进入本地记录页待播分段
- **THEN** 该条目仍呈现于待播列表最前

#### Scenario: 重复添加幂等

- **WHEN** 待播列表已包含某视频且用户在其他页再次右键添加同一视频
- **THEN** 列表不产生重复条目且既有条目顺序不变

#### Scenario: 存储损坏容错

- **WHEN** 待播持久化文件内容损坏不可解析
- **THEN** 待播分段呈现空列表（含空态提示）而非崩溃，随后的添加可正常写入并保留

### Requirement: 跨页"添加到待播"入口

动态、特别关注、稍后再看、在线历史、本地历史页的视频卡片右键菜单 MUST 呈现"添加到待播"项（沿用既有卡片右键菜单形态）；点击 MUST 为纯本地操作，即时写入待播持久化，MUST NOT 发起任何网络请求。本地记录页**待播视图**自身的卡片右键菜单 MUST NOT 呈现"添加到待播"项；**历史视图**的卡片右键菜单 MUST 呈现该项（重新入队途径，幂等语义同跨页添加）。不可窗口播放的条目（如专栏、直播类卡片）MUST 同样允许添加（作为本地收集语义；播放全部时按播放语义跳过）。

#### Scenario: 各卡片页可添加

- **WHEN** 用户在动态页（或特别关注、稍后再看、在线历史、本地历史页）右键某视频卡片
- **THEN** 菜单含"添加到待播"，点击后进入本地记录页待播分段可见该条目且位于列表最前

#### Scenario: 待播视图自身无该项

- **WHEN** 用户在本地记录页待播分段右键某卡片
- **THEN** 菜单不含"添加到待播"项

#### Scenario: 历史视图保留该入口

- **WHEN** 用户在本地记录页历史分段右键某归档卡片并点击"添加到待播"
- **THEN** 该条目进入待播列表（已在列时为幂等无操作）

#### Scenario: 添加零网络

- **WHEN** 用户点击"添加到待播"
- **THEN** 不发出任何网络请求

### Requirement: 待播视图瀑布流与卡片移除

待播分段 MUST 以瀑布流（沿用 MasonryPanel 与 HistoryCard）呈现全部待播条目，列表顺序即显示顺序（最新添加在最前）；页面 MUST NOT 发起任何网络请求，MUST NOT 提供刷新按钮。待播卡片封面左上角 MUST 呈现"关闭"移除按钮（仅待播视图的卡片呈现），点击 MUST 立即从列表与持久化中移除该条目且 MUST NOT 弹出确认；点击移除按钮 MUST NOT 触发卡片跳转或封面预览。卡片其余交互 MUST 沿用既有行为：点击卡片在系统浏览器打开对应页面、点击封面全屏预览、右键"在新窗口播放"按既有起播路径可用（含 PGC 条目定位与权益拒播序列）。待播列表为空时 MUST 呈现本地化空态提示（含"右键卡片添加"引导文案）。在其他页新增条目后切回本页（帧缓存重入）MUST 呈现新增条目。

#### Scenario: 关闭按钮移除条目

- **WHEN** 用户点击某待播卡片封面左上角的关闭按钮
- **THEN** 该卡片从列表消失，重启应用后不再呈现（移除已持久化）

#### Scenario: 移除不误触跳转与预览

- **WHEN** 用户点击关闭按钮
- **THEN** 不打开浏览器、不弹出封面预览

#### Scenario: 空列表提示

- **WHEN** 待播列表为空（从未添加或已全部移除）
- **THEN** 待播分段呈现本地化空态提示与添加方式引导

#### Scenario: 他页添加后重入可见

- **WHEN** 用户在稍后再看页添加一条视频后切到本地记录页
- **THEN** 待播分段呈现新条目于列表最前，无需手动刷新

### Requirement: 播放全部与清空

待播分段的冻结标题带右上角 MUST 呈现"播放全部"与"清空"两个按钮（经既有宽度同步机制与瀑布流右缘对齐，仅待播分段选中时呈现）。"播放全部"MUST 打开（或复用既有单实例）播放窗口，将全部待播条目按列表顺序追加进播放列表并从列表首项开播；追加 MUST 沿用既有集合播放的去重语义，MUST NOT 清空播放窗口中既有无关条目；不可窗口播放的条目 MUST 被跳过且 MUST NOT 阻塞其余条目起播；列表中无可播条目时 MUST NOT 打开播放窗口。"清空"MUST 先呈现二次确认对话框，用户确认后才移除全部条目并持久化；取消确认 MUST 不做任何变更。两个按钮在待播列表为空时 MUST 禁用。

#### Scenario: 播放全部从头开播

- **WHEN** 待播列表含 3 条可播条目且用户点击"播放全部"
- **THEN** 播放窗口打开并起播列表首项，播放列表按页面顺序包含全部可播条目

#### Scenario: 跳过不可播条目

- **WHEN** 待播列表同时含专栏类条目与普通稿件且用户点击"播放全部"
- **THEN** 仅可播条目进入播放列表并起播，专栏条目被跳过、不出错

#### Scenario: 清空需二次确认

- **WHEN** 用户点击"清空"并在确认对话框中点击取消
- **THEN** 对话框关闭，列表与持久化均不变更

#### Scenario: 确认清空后生效

- **WHEN** 用户在确认对话框中点击确认
- **THEN** 待播列表清空、空态提示呈现，重启应用后列表仍为空

#### Scenario: 空列表按钮禁用

- **WHEN** 待播列表为空
- **THEN** "播放全部"与"清空"均呈禁用态不可点击

### Requirement: 待播/历史双分段切换

本地记录页顶部 MUST 提供 SelectorBar 双分段："待播"与"历史"。分段切换 MUST 为纯客户端操作：零网络请求、零持久化重读，两分段各自的全量列表互不影响并行保持。当前选中分段 MUST 高亮标识。搜索 MUST 作用于当前选中分段的全量已加载列表，切换分段后 MUST 按当前搜索词对新分段重新投影。"播放全部"与"清空"按钮 MUST 仅在"待播"分段选中时呈现。

#### Scenario: 切换分段纯客户端

- **WHEN** 用户在"待播"与"历史"之间来回切换
- **THEN** 无网络请求与文件读取，对应列表即时呈现且各自浏览状态互不干扰

#### Scenario: 切段后搜索重放

- **WHEN** 用户已提交搜索词后切到另一分段
- **THEN** 新分段按该词投影其全量列表（无匹配则呈现"未找到匹配"提示）

#### Scenario: 工具栏按钮分段可见性

- **WHEN** 选中"历史"分段
- **THEN** "播放全部"与"清空"按钮不呈现；切回"待播"后恢复呈现

### Requirement: 播放窗口关闭归档

每次播放窗口关闭时 MUST 将其会话播放列表中的全部条目快照归档到本地持久化：每条归档 MUST 包含条目标识（足以重建卡片与起播，含 PGC 条目的原始定位信息）、归档时刻与该条目在归档时刻的播放位置（正在播放条目取实时位置，其余条目取会话内最后已知位置，无则 0）。归档 MUST 以 VideoKey 聚合：同一视频的多次归档累积为一条记录的多次会话（按归档时间降序）。关窗时处于番剧剧集模式（播放番剧的实例）MUST NOT 归档——该次关闭完全跳过。归档 MUST NOT 弹出任何 UI、MUST NOT 阻塞或延迟关窗序列；归档写入失败 MUST NOT 影响关窗。归档持久化损坏时 MUST 容错回退空表（与待播存储同口径）。

#### Scenario: 关窗归档全部条目

- **WHEN** 播放窗口的播放列表含 3 个条目且用户关闭窗口
- **THEN** 历史分段呈现这 3 条归档记录，归档时间为本次关窗时刻

#### Scenario: 同视频多次归档聚合

- **WHEN** 同一视频先后出现在两次关窗的播放列表中
- **THEN** 历史分段中该视频为一条记录，badge 计 2 次，tooltip 列出两次归档的时间与位置

#### Scenario: 剧集模式关窗不归档

- **WHEN** 用户从番剧页起播剧集（剧集模式激活）后关闭播放窗口
- **THEN** 不产生任何归档记录

#### Scenario: 未播放条目位置为零

- **WHEN** 关窗时播放列表含本会话从未起播的条目
- **THEN** 该条目仍被归档，其归档位置为 0

#### Scenario: 归档不阻塞关窗

- **WHEN** 关闭播放窗口
- **THEN** 窗口关闭时序与既有行为一致（隐藏即时、后台清理不受影响），无新增等待或失败提示

### Requirement: 历史视图概要与恢复播放

历史分段 MUST 以瀑布流呈现全部归档记录，按最近归档时间降序排列；卡片 MUST 复用既有卡片形态（参考本地历史页卡片：封面、标题、UP 主、进度呈现），且封面右上角 MUST 常驻归档次数 badge（如"3 次"）与 tooltip——tooltip MUST 逐次列出该视频每次归档的时间与当时播放位置。点击卡片（封面除外）MUST 在系统浏览器打开对应页面、点击封面 MUST 全屏预览（沿用既有行为）。恢复播放 MUST 经卡片右键"在新窗口播放"沿用既有起播路径与三级续播语义（会话内存 > 本地持久化位置 > 云端缓存进度）。历史分段 MUST NOT 发起任何网络请求、MUST NOT 提供刷新按钮。归档记录为空时 MUST 呈现本地化空态提示（含"关闭播放窗口时自动归档播放列表"引导）。历史分段 MUST 在新的归档落盘后再次进入页面时呈现最新记录（帧缓存重入同步）。

#### Scenario: 归档概要与 badge

- **WHEN** 历史分段中某视频已聚合 3 次归档
- **THEN** 其卡片右上角 badge 呈现"3 次"，tooltip 逐行列出 3 次归档时间与当时的播放位置

#### Scenario: 恢复播放续播

- **WHEN** 用户右键历史分段某记录选择"在新窗口播放"
- **THEN** 播放窗口起播该视频并按既有三级续播语义跳转到最后已知播放位置附近

#### Scenario: 历史卡片跳转与预览

- **WHEN** 用户点击历史分段某卡片（非封面）或其封面
- **THEN** 分别在系统浏览器打开对应页面、弹出封面全屏预览

#### Scenario: 空态提示

- **WHEN** 无任何归档记录
- **THEN** 历史分段呈现空态提示与自动归档引导

#### Scenario: 新归档重入可见

- **WHEN** 用户关闭播放窗口产生归档后切到本地记录页历史分段
- **THEN** 新归档记录呈现于列表最前

### Requirement: 分段作用域标题搜索

本地记录页 MUST 接受主窗口标题栏搜索框提交的搜索词，对**当前选中分段的全量已加载列表**的**标题或 UP 主名称**做不分大小写的子串匹配筛选展示，满足任一条件即显示；搜索 MUST 为已加载数据的即时投影，搜索提交本身 MUST NOT 发起网络请求、MUST NOT 触发任何列表拉取或持久化重读。投影为空时 MUST 呈现本地化"未找到匹配"提示（含当前分段已加载条数）。提交空词 MUST 恢复展示当前分段全部条目。搜索词 MUST 为页面帧缓存的一部分：切页或切段再返回时按其重新投影。

#### Scenario: 标题或 UP 主匹配

- **WHEN** 用户在待播分段提交关键词"教程"
- **THEN** 仅渲染标题或 UP 主名称含"教程"（忽略大小写）的待播条目，其余隐藏，搜索提交本身不发起网络请求

#### Scenario: 空结果未找到匹配

- **WHEN** 提交的关键词在当前分段全量列表中无任何匹配
- **THEN** 呈现本地化"未找到匹配"提示（含该分段已加载条数），不发起任何网络请求

#### Scenario: 清空恢复

- **WHEN** 用户清空搜索框后提交
- **THEN** 当前分段恢复展示全部已加载条目

### Requirement: 帧缓存与浏览状态保持

用户从本地记录页切换到其他导航菜单项再返回时，当前分段选择、两分段各自已加载的列表与已提交的搜索词 MUST 完整保持，MUST NOT 重新读取持久化（除非其间持久化内容发生了变化——如在其他页新增了待播条目或播放窗口产生了新归档，此时对应分段 MUST 呈现最新列表）。页面滚动位置 SHOULD 尽力保持但允许 XAML Frame 缓存限制导致的位置重置。

#### Scenario: 切页返回状态保持

- **WHEN** 用户在本地记录页历史分段浏览至列表中部后切换到"设置"页再返回
- **THEN** 页面仍停在历史分段且列表保持（无重复读取、无顺序变化），搜索词（如有）保持，滚动位置尽力保留或重置到顶部
