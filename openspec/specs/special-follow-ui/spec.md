# special-follow-ui Specification

## Purpose
定义"特别关注"页面的 UI 行为契约：本地维护的特别关注 UP 列表与管理弹层（本地能力）、横向头像条及其选中态互补材质突出背景、**单 SelectorBar 三档主视图（投稿/合集/专栏）与统一标准分页**（投稿=投稿视频端点+分区筛选+排序；合集=卡片夹 widget 与批量起播；专栏=专栏文集端点）、标题栏搜索投影，以及浏览状态在导航切换中的帧缓存保持。2026-09-07 v3：动态视图（空间动态流）因端点持续 412 风控整体移除——一级菜单与"全部图文/动态"两视图不再存在，"专栏"并入唯一 SelectorBar 第三档。

## Requirements

### Requirement: 本地 UP 列表与种子导入

特别关注页的 UP 集合 MUST 为**客户端本地维护**（与服务端"特别关注分组"解耦）：列表以 mid/昵称/头像 URL 快照持久化于应用本地设置，跨会话保留。页面首次进入且本地列表为空时，MUST 以服务端特别关注分组（分组明细端点，tagid=-10）做**一次性种子导入**（导入成功后写回本地，此后服务端分组变更不影响本地列表）；种子请求失败或分组为空时 MUST 呈现本地化空态引导（提示经管理入口添加），MUST NOT 阻塞页面骨架呈现。本地列表 MUST NOT 落库云端历史数据库（零 SQLite 写入）。

#### Scenario: 首次进入种子导入

- **WHEN** 本地列表为空且用户首次进入特别关注页
- **THEN** 页面经特别关注分组明细端点拉取分组成员（含头像与昵称），写入本地设置并以头像条呈现；此后再次进入直接读本地快照，不再请求该端点

#### Scenario: 种子为空或失败

- **WHEN** 服务端特别关注分组为空或请求失败
- **THEN** 页面呈现本地化空态引导（指向管理入口），页面骨架（头像条与管理按钮）仍可交互

#### Scenario: 跨会话保留

- **WHEN** 用户编辑本地列表后重启应用再进入特别关注页
- **THEN** 头像条按本地快照呈现，无网络请求发出即可展示

### Requirement: 管理弹层（选择已关注 UP）

头像条 MUST 提供"管理"入口按钮，点击 MUST 打开选择弹层（ContentDialog 形态）：弹层 MUST 经关注明细端点**分页**拉取当前账号的关注列表（每页携带昵称与头像），支持继续加载下一页；搜索 MUST 走**服务端关注搜索端点**（按昵称关键词查询，经短防抖触发，MUST NOT 逐键请求）——关键词非空时弹层呈现服务端匹配结果并支持翻页加载更多（受服务端最多 5 页限制），清空关键词 MUST 回到已加载的分页浏览列表；每个成员 MUST 提供复选开关，勾选状态以跨模式池维护（在搜索结果上的勾选 MUST 在后续搜索、翻页与模式切换间保持），确认 MUST 按合并语义写回本地设置并刷新头像条（保留当前选中 UP 若其仍在列表中）——**已加载进弹层的成员按其复选框增删，从未加载进弹层的既有本地成员（如种子导入、更早会话的勾选、未翻到的深页）MUST 保持本地现状不被移除**（移除仅发生于该成员在弹层中可见且被显式取消勾选），取消 MUST 不产生任何变更。弹层拉取、搜索与翻页 MUST 呈现加载指示，登录失效与请求失败 MUST 呈现本地化提示且保留已呈现内容可继续勾选（加载更多兼做重试）。

#### Scenario: 分页浏览与服务端搜索

- **WHEN** 用户打开管理弹层向下滚动到底、随后在搜索框输入昵称片段并停顿
- **THEN** 弹层先呈现下一页关注成员（含加载指示）；停顿防抖到期后弹层呈现服务端搜索的匹配结果（含匹配计数），输入过程中不发起请求；清空关键词后回到分页浏览列表

#### Scenario: 搜索结果勾选跨模式保持

- **WHEN** 用户在搜索结果中勾选某 UP、再搜索其他关键词或清空回到浏览列表、随后确认保存
- **THEN** 该 UP 的勾选仍然生效并进入本地特别关注列表

#### Scenario: 未加载进弹层的本地成员保存不被清空

- **WHEN** 本地特别关注列表含某 UP（经搜索结果勾选保存或种子导入而来，当前弹层会话未将其加载进任何浏览页或搜索结果），用户在默认展示的首页勾选另一位 UP 并确认保存
- **THEN** 未加载的那位 UP 仍保留在本地特别关注列表中（仅当其在弹层中可见且被取消勾选时才会被移除）

#### Scenario: 勾选保存生效

- **WHEN** 用户勾选两位 UP、取消勾选一位既有 UP 后确认
- **THEN** 本地设置更新为最新勾选集合，头像条即时增删对应头像；被取消勾选且当前选中的 UP 不在列表时选中态按规则回落到首项

#### Scenario: 取消不变更

- **WHEN** 用户修改勾选后点击取消
- **THEN** 本地列表与头像条维持进入弹层前的状态

#### Scenario: 拉取失败可重试

- **WHEN** 弹层打开时关注列表请求失败
- **THEN** 弹层呈现本地化失败提示与重试入口，已加载页（如有）保留可继续勾选

### Requirement: 横向头像条与选中态

页面顶部 MUST 呈横向可滚动的头像条：条内仅显示头像（MUST NOT 显示昵称或任何文字），头像圆形、尺寸统一、水平间距均匀（视觉等距），条内滚动 MUST 启用且滚动条 MUST 不可见；头像条右端固定"管理"入口（图标按钮，不随条滚动）。头像条 MUST 呈**单选 tab 语义**：点击头像即选中并驱动主视图切换到该 UP 的内容；选中头像 MUST 呈突出背景，未选中头像无背景。突出背景 MUST 采用与页面基底**互补的材质**：基底为 Mica（当前主窗口恒为 Mica）时选中头像的胶囊背景与主视图容器背景 MUST 采用 Acrylic 画笔，二者 MUST 视觉连续（自选中头像延伸至主视图的连续浮层观感）；若未来基底切换为 Acrylic，突出背景 MUST 改用近似 Mica 的分层填充。默认选中项 MUST 为列表首项；当前选中 UP 被移出本地列表时选中态 MUST 回落到新的首项。

#### Scenario: 头像条布局约束

- **WHEN** 本地列表含多个 UP 且超出可视宽度
- **THEN** 头像条可水平滚动且不显示滚动条，条内仅有头像与右端管理按钮，无任何文字标签

#### Scenario: 单选切换驱动主视图

- **WHEN** 用户点击另一个头像
- **THEN** 该头像呈选中态（互补材质突出背景），主视图切换为该 UP 的当前分块内容，原选中头像恢复无背景

#### Scenario: 选中态材质互补

- **WHEN** 主窗口背景为 Mica 且用户选中某头像
- **THEN** 选中头像胶囊与主视图容器呈 Acrylic 质感浮层，与 Mica 基底形成材质对比，两者视觉连续

#### Scenario: 选中 UP 被移除后的回落

- **WHEN** 管理弹层确认后当前选中 UP 不在新列表中
- **THEN** 选中态回落到列表新的首项，主视图随之切换

### Requirement: 主视图三档分块

主视图 MUST 以单一 SelectorBar 呈现三个分块：**投稿、合集、专栏**（对齐 B 站 web 空间页分块；动态类视图已因空间动态流端点的持续 412 风控整体移除，MUST NOT 提供任何基于空间动态流的视图）。分块切换 MUST 不丢状态：各分块已加载内容、筛选/排序与分页位置在会话内独立保持（按 UP 会话缓存）；切换头像时各分块数据按各自缓存语义独立处理。主视图容器 MUST 采用互补材质突出背景（见头像条需求）。页面 MUST 提供刷新按钮（右缘与瀑布流对齐，沿用宽度同步机制），刷新 MUST 只重拉**当前 UP 当前分块**并保旧卡整体替换（沿用在线历史页刷新语义），登录失效与请求失败 MUST 呈本地化提示。

#### Scenario: 三档分块构成

- **WHEN** 用户进入特别关注页展开主视图
- **THEN** 单一 SelectorBar 依次呈现"投稿""合集""专栏"三档，无一级侧栏菜单、无"全部图文/动态"档

#### Scenario: 分块切换保状态

- **WHEN** 用户在"投稿"浏览若干页后切到"合集"再切回"投稿"
- **THEN** 投稿分块仍呈现其页内容、分区/排序与页码，不重新拉取

#### Scenario: 刷新当前分块

- **WHEN** 用户在"专栏"点击刷新
- **THEN** 仅当前 UP 的专栏文集被重拉（保旧卡整体替换），其余分块缓存不受影响

### Requirement: 视频-投稿视图（投稿视频端点与分区排序分页）

投稿视图 MUST 以投稿视频端点为数据源（服务端 30 条/页分页），MUST NOT 使用空间动态流。视图顶部 MUST 提供**分区筛选行**：分区档位来自响应自带的分区索引（"全部分区"档 + 各分区名与计数，响应即得、MUST NOT 逐视频补查），以窄间隙切换按钮呈现（恒有且仅有一档选中），水平可滚动、不显示滚动条；分区行与排序控件 MUST 各自独立容器（列）呈现，任意窗口宽度下 MUST NOT 相互重叠；MUST 提供**排序切换**：按时间（最新发布）/按播放（最多播放）/按收藏（最多收藏）。切换分区或排序 MUST 重置到第一页并重新拉取。卡片 MUST 复用既有卡片控件与交互整链：封面预览、非封面左键播放（archive 管线直通）、右键打开原链接且无新窗口播放项；卡片副信息 SHOULD 呈现播放量与弹幕数。视图底部 MUST 呈标准分页栏（30 条/页；首页/上一页/下一页/末页与页信息；翻页 MUST 发起对应页请求；单页内容不足 30 条或已达总数时对应方向 MUST 禁用）。空结果 MUST 呈本地化空态提示。

#### Scenario: 分区筛选

- **WHEN** 投稿视图已加载且用户选择分区行中某分区
- **THEN** 列表按该分区重新拉取第一页，分区档位与计数来自响应分区索引（无逐视频网络补查）

#### Scenario: 排序切换

- **WHEN** 用户将排序从"最新发布"切到"最多播放"
- **THEN** 列表按播放排序重新拉取第一页

#### Scenario: 标准分页

- **WHEN** 投稿视图总投稿数超过 30 且用户点击"下一页"
- **THEN** 发起第二页请求并整体替换当前页卡片，页信息更新（共 N 页）；处于末页时"下一页/末页"禁用

#### Scenario: 卡片交互整链复用

- **WHEN** 用户预览封面、点击卡片非封面主体或右键打开链接
- **THEN** 行为与既有卡片页同构：分别预览原图、播放窗口按既有 archive 管线起播、浏览器打开原页

### Requirement: 视频-合集视图与卡片夹 widget

合集分块 MUST 合并展示选中 UP 的**合集与系列**（对齐 B 站 web"合集和系列"分块），以瀑布流（沿用 MasonryPanel）呈现；视图 MUST 按列表端点服务端分页（page_num/page_size 推进；page_size 受服务端上限 **20 条/页**——超限返回空 data 的 -400，实测偏差已记录，分页栏页数按 20 计算），底部呈标准分页栏（同投稿视图；MUST NOT 自动续拉、MUST NOT 使用"加载更多"形态）。每个条目 MUST 呈现为**卡片夹 widget**：主体为三张部分重叠的卡片——首张（最上层）展示合集封面，其余两张为带描边的半透明灰色卡片、依次错位叠在后侧形成堆叠空间感；卡片夹下方显示合集标题（超长截断并可悬停查看全名）与分类角标（zh-CN 如"合集"/"系列"，含视频数）；卡片夹中央 MUST 呈播放图标按钮；点击播放按钮 MUST 仅触发播放序列，MUST NOT 同时触发卡片跳转（播放点击与卡片跳转互斥，事件不得自按钮冒泡至卡片跳转处理）。点击播放按钮 MUST 依次完成：拉全该合集/系列的视频分页（进度有加载指示）→ 按 video_key 去重批量加入会话播放列表 → 自合集首集起播（复用单例播放窗口：未开则新开、已开则复用激活）。拉取或起播失败 MUST 呈本地化提示且 MUST NOT 清空既有播放列表。合集列表为空时 MUST 呈本地化空态提示。

#### Scenario: 卡片夹视觉契约

- **WHEN** 合集分块呈现某条目
- **THEN** 该条目呈三张部分重叠卡片：首张为合集封面、后两张为半透明灰色带描边卡，卡片夹下方为合集标题与"合集/系列"角标（含视频数），中央有播放图标按钮

#### Scenario: 播放按钮批量起播

- **WHEN** 用户点击某合集卡片夹中央的播放按钮
- **THEN** 应用拉全该合集视频（分页推进、有加载指示），全部条目去重加入播放列表并自首集起播；播放窗口被激活（未开则新开）；点击不打开浏览器页面（卡片跳转不触发）

#### Scenario: 部分条目已在列表

- **WHEN** 播放列表已含该合集的 2 条视频，用户再次点击其播放按钮
- **THEN** 既有 2 条不重复入列，其余条目追加，起播定位到该合集首集

#### Scenario: 合集为空或拉取失败

- **WHEN** 点击播放按钮后合集视频拉取失败或合集内视频数为 0
- **THEN** 呈本地化失败/空态提示，播放列表与当前播放不发生变化

#### Scenario: 无合集空态

- **WHEN** 选中 UP 无任何合集与系列
- **THEN** 合集分块呈本地化空态提示，无卡片夹呈现

### Requirement: 专栏视图（专栏文集端点）

专栏分块 MUST 以专栏文集端点为数据源（一次全量返回文集列表），客户端本地 30 条/页分页；每个文集 MUST 呈现封面、名称、包含文章数、阅读量与字数（副信息），点击 MUST 在浏览器打开对应文集页。分块底部 MUST 呈标准分页栏（本地分页末页禁用向后方向）。空结果 MUST 呈本地化空态提示；提示 MUST 居中于冻结工具栏与分页栏之间的可见内容视口，MUST NOT 随零高或已滚动的内容区域偏移，长文字 MUST 限宽换行。

#### Scenario: 专栏文集列表

- **WHEN** 该 UP 有专栏文集且用户进入"专栏"档
- **THEN** 呈现文集卡（封面/名称/文章数/阅读量/字数），本地 30 条/页分页；点击卡片在浏览器打开该文集页

#### Scenario: 无文集空态

- **WHEN** 该 UP 没有专栏文集
- **THEN** 专栏分块呈本地化空态提示，无卡片呈现

#### Scenario: 暂无专栏不越界

- **WHEN** 专栏列表为空，尤其是从已滚动的投稿分块切换进入
- **THEN** “暂无专栏”居中显示在内容视口内，不超出上边缘，长提示可换行

### Requirement: 标题或 UP 主名称搜索

特别关注页 MUST 接受主窗口标题栏搜索框提交的搜索词：全部五个视图 MUST 对**当前分页已加载条目**做标题或 UP 主名称（合集/文集条目按名称）的不分大小写子串投影——纯内存投影，搜索提交本身 MUST NOT 发起网络请求、MUST NOT 触发翻页或续拉（与本地历史页"仅当前分页"语义同构）。空投影时 MUST 呈本地化"未找到匹配"提示（含当前页条数）。提交空词 MUST 恢复展示当前页全部条目。搜索词 MUST 为帧缓存的一部分；切换页码后新页条目按当前搜索词重新投影。

#### Scenario: 当前页投影

- **WHEN** 投稿视图第 2 页已加载且用户提交关键词
- **THEN** 仅渲染第 2 页中标题或 UP 主名称匹配的条目，搜索提交不发起任何网络请求，不跨页搜索其他页条目

#### Scenario: 空结果未找到匹配

- **WHEN** 当前页条目均不匹配搜索词
- **THEN** 呈本地化"未找到匹配"提示（含当前页条数），零网络请求

#### Scenario: 清空恢复

- **WHEN** 用户清空搜索框后提交
- **THEN** 当前页恢复展示全部条目

### Requirement: 帧缓存与浏览状态保持

用户从特别关注页切换到其他导航菜单项再返回时，本地 UP 列表、当前选中 UP、当前分块、三个分块已加载内容与筛选/排序/分页状态、已提交搜索词 MUST 完整保持，MUST NOT 重新拉取（数据已在会话缓存）；页面滚动位置 SHOULD 尽力保持但允许 XAML Frame 缓存限制导致的位置重置。

#### Scenario: 切页返回状态保持

- **WHEN** 用户在特别关注页浏览某 UP 投稿分块（已选"视频"档）后切到"设置"再返回
- **THEN** 选中 UP、分块、已加载动态、筛选档与搜索词均保持，不重新发起请求

#### Scenario: 切换头像后的会话缓存

- **WHEN** 用户从 UP A 切到 UP B 再切回 A
- **THEN** A 的投稿与合集已加载内容从会话缓存恢复，不重新拉取；B 的内容同样缓存待回切

### Requirement: 特别关注头像七天缓存

特别关注页及其管理弹层的头像 MUST 使用按用户 ID 区分的持久化本地缓存；最近一次成功下载后的七天内 MUST 复用缓存，跨切页与重启不重复下载。缓存过期后 MUST 异步更新，期间继续显示旧图；失败 MUST 保留旧图且不得将失败时间作为成功刷新时间。缺失缓存 MUST 按需下载。缓存下载 MUST 校验图片并原子写入，同一头像并发请求 MUST 合并，过期回应 MUST NOT 覆盖较新的数据。缓存 MUST 位于应用数据目录并遵守测试数据隔离。

#### Scenario: 七天内重用

- **WHEN** 用户重新打开特别关注页或应用且头像下载成功不足七天
- **THEN** 头像从本地加载，不重复下载相同用户头像

#### Scenario: 到期刷新和离线回退

- **WHEN** 头像缓存达到七天且页面需要显示头像
- **THEN** 后台更新头像，期间展示旧图，失败保留旧图，成功替换并重置七天有效期

#### Scenario: 管理弹层共享

- **WHEN** 页面和管理弹层同时显示同一用户
- **THEN** 二者共用缓存及请求，成功更新后的图像一致

### Requirement: 内嵌默认头像

特别关注头像条与管理弹层 MUST 使用项目内嵌的 `noface.jpg` 作为头像源缺失、加载中及加载错误时的占位图，沿用头像圆形裁剪。默认图片 MUST 随应用打包并离线可用；默认图 MUST NOT 写入用户头像缓存或改变七天有效期、下载与失败回退逻辑。已有有效缓存时 MUST 继续优先显示缓存。

#### Scenario: 无头像或加载失败

- **WHEN** 特别关注用户头像源为空、加载中或加载失败且无可用旧头像
- **THEN** 展示内嵌 noface 图片，后续头像加载成功后正常替换

### Requirement: 当前 UP 名称与视频作者展示

特别关注页 SHALL 在主视图右上角显示当前选中 UP 主的已保存名称；投稿视图中名称 SHALL 位于分区标签右侧，合集与专栏中 SHALL 保留该名称。名称 SHALL 随头像选择及本地资料更新而更新；无选中 UP 时 MUST NOT 残留旧名称。长名称 MUST 单行省略且可悬停查看全名，MUST NOT 挤压或覆盖分区标签。

投稿及合集内视频缺少作者名时 SHALL 按条目作者 UID 匹配本地 UP 资料补齐姓名和头像；仅条目缺少作者 UID 时可使用当前 UP。已有有效作者名 MUST 保留，不同 UID 的条目 MUST NOT 被标记为当前 UP。补齐后的资料 SHALL 同时用于卡片、本地投稿作者名搜索及合集批量播放条目，MUST NOT 为显示名称增加网络请求。个人空间的独立资料来源 MUST 保持。

#### Scenario: 选择与切页返回

- **WHEN** 用户选择另一位 UP，或切到其他页面再返回
- **THEN** 主视图右上角名称与当前选中头像一致，投稿/合集/专栏切换后仍显示该名称

#### Scenario: 长名称和空列表

- **WHEN** 昵称很长或用户移除了所有特别关注成员
- **THEN** 长名称在右侧限定宽度内省略并可悬停查看，空列表不显示上一位 UP 名称

#### Scenario: 卡片与搜索补齐

- **WHEN** 投稿或合集视频已有作者 UID，但条目未携带姓名且本地资料存在
- **THEN** 卡片显示对应昵称而非“未知作者”，投稿可按该昵称搜索，合集批量播放也携带对应作者资料

#### Scenario: 作者隔离

- **WHEN** 条目明确属于不同 UID 或已经携带有效作者名
- **THEN** 不用当前 UP 的姓名覆盖该条目；切换 UP 或个人空间不串用其他用户资料

#### Scenario: 名称避让滚动条

- **WHEN** 主视图右侧滚动条显示或悬停展开
- **THEN** UP 名称 SHALL 保留 24px 右外边距，不被滚动条遮挡；窄窗口及长名称仍单行省略
