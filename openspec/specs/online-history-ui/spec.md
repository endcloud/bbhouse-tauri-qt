# online-history-ui Specification

## Purpose
定义"在线历史"页的浏览契约：以 B 站云端 cursor API 为数据源的只读瀑布流浏览——无限滚动、刷新与回到顶部、加载/失败/到底状态呈现，卡片交互与本地历史一致。

## Requirements

### Requirement: 云端数据源与只读性

在线历史页 MUST 以云端观看历史 cursor API 为数据源按需拉取条目并渲染为与本地历史一致的瀑布流卡片（列宽 300px、自适应列数、最短列放置、整体居中）；MUST NOT 将拉取到的数据写入本地数据库，MUST NOT 触发同步或影响本地缓存口径；页面 MUST NOT 显示分页栏。

#### Scenario: 进入页面拉取首页

- **WHEN** 用户切到"在线历史"页
- **THEN** 页面向云端请求第一页（30 条）并渲染卡片，本地数据库无任何写入

#### Scenario: 卡片视觉一致

- **WHEN** 同一条目分别出现在在线历史与本地历史页
- **THEN** 卡片元素与布局一致（封面/角标/标签/进度等，展示属性来自同一 ViewModel）

### Requirement: 无限滚动加载

列表 MUST 以无限滚动方式续载：每页 30 条，滚动位置接近列表底部（最后三行高度内）时 MUST 自动请求下一页并追加渲染（当前搜索词下匹配的条目进入可见列表）；云端游标耗尽或返回空页时 MUST 停止续载并呈现本地化的"已到底"提示；连续两页出现重复条目（同 video_key）时 MUST 去重；游标与上一页相同（防死循环信号）时 MUST 视为到底。当前投影（搜索叠加）为空且未到底时 MUST 自动续载并链式推进（连续自动轮设上限、轮间短暂步进、不依赖滚动或布局事件），直到出现匹配、到底或达上限；达上限仍为空 MUST 呈现本地化"未找到匹配"提示，用户手势（滚动、提交搜索、刷新）MUST 可从保留的游标进度恢复续载。

#### Scenario: 滚动触发续载

- **WHEN** 用户滚动至距列表底部最后三行范围内
- **THEN** 自动请求下一页并追加卡片，滚动无需用户再次操作

#### Scenario: 云端到底

- **WHEN** 游标耗尽或返回空页后用户继续滚动
- **THEN** 不再发起新请求，列表底部显示本地化到底提示

#### Scenario: 重复条目去重

- **WHEN** 续载返回的条目中存在与已渲染条目相同的 video_key
- **THEN** 该条目不重复渲染

#### Scenario: 空投影自动续拉

- **WHEN** 用户提交了在已加载条目中无匹配的搜索词且云端未到底
- **THEN** 页面不依赖滚动或布局事件，自动连续续载直至出现匹配、到底或达连续自动轮上限（达上限呈现"未找到匹配"提示，重新提交搜索或刷新可恢复）

### Requirement: 工具栏与刷新

页面顶部工具栏 MUST 仅包含"刷新"一个按钮：仅图标、无文字，水平位置右对齐于瀑布流内容区右缘；点击刷新 MUST 重置游标、清空列表并重新拉取首页；加载进行中 MUST 防止重复触发（刷新与续载互斥）。"回到顶部"悬浮按钮 MUST 沿用本地历史页行为（下滚出现、回顶隐藏、点击回顶）。

#### Scenario: 刷新重置列表

- **WHEN** 用户点击仅图标的刷新按钮
- **THEN** 列表清空并以首页重新拉取，滚动位置回到顶部

#### Scenario: 刷新按钮形态

- **WHEN** 页面渲染工具栏
- **THEN** 工具栏仅含一个图标按钮（无文字标签），其右缘与瀑布流内容区右缘对齐

#### Scenario: 回到顶部行为沿用

- **WHEN** 列表下滚后
- **THEN** 回顶悬浮按钮出现，点击后列表回到顶部并隐藏，与本地历史页一致

### Requirement: 状态与错误呈现

页面 MUST 呈现：首页/续载加载中指示、登录失效提示（点击或刷新可重试）、请求失败提示（不中断已加载内容，可重试续载）、空结果提示、未找到匹配提示（空投影自动续载达上限时）；全部文案 MUST 走 zh-CN/en-US 双语资源。卡片交互 MUST 与本地历史共享卡片一致：有效 archive/pgc 的非封面左键调用新窗口播放，非视频沿用浏览器行为，封面点击仅预览原图；右键保留打开链接并移除播放菜单项，失效视频不播放。

#### Scenario: 登录失效提示

- **WHEN** cookie 失效时进入页面或续载
- **THEN** 显示本地化登录失效提示，再次刷新时重新尝试

#### Scenario: 续载失败不断列表

- **WHEN** 某次续载请求失败
- **THEN** 已加载卡片保持可见，显示可重试的失败提示，后续滚动可重新触发续载

#### Scenario: 卡片交互一致

- **WHEN** 用户点击在线历史卡片封面与文字区域、右键卡片
- **THEN** 分别触发封面预览、有效视频的独立窗口播放以及无播放项的右键菜单；右键打开链接仍可用，行为与本地历史一致

### Requirement: 标题或 UP 主名称搜索

在线历史页 MUST 接受主窗口标题栏搜索框提交的搜索词，并仅对**当前已加载条目池**的**标题或 UP 主名称**做不分大小写的子串匹配筛选展示，满足任一条件即显示；搜索 MUST 为当前已加载数据的即时投影，搜索提交本身 MUST NOT 发起网络请求，MUST NOT 改变无限滚动续载、去重、刷新或游标进度逻辑；叠加投影为空且未到底时按"无限滚动加载"的空投影自动续载规则继续（新拉取条目入池后按当前搜索词投影）。提交空词 MUST 恢复展示全部已加载条目。搜索词与已加载列表均为页面帧缓存的一部分：切页再返回时筛选效果与列表 MUST 保持；刷新重置列表后 MUST 在当前搜索词下重新筛选展示，搜索词不丢失。

#### Scenario: 已加载条目筛选（标题或 UP 主匹配）

- **WHEN** 用户已滚动加载若干页后提交关键词"up主"
- **THEN** 仅渲染已加载条目中标题或 UP 主名称含"up主"的部分，其余隐藏，搜索提交本身不发起网络请求

#### Scenario: 清空恢复全部

- **WHEN** 用户提交空关键词或清空搜索框后提交
- **THEN** 列表恢复展示全部已加载条目

#### Scenario: 续载仍遵守搜索

- **WHEN** 用户提交关键词后继续滚动触发下一页续载
- **THEN** 新追加条目仍按该关键词筛选展示（标题或 UP 主名称），搜索词不丢失，续载互斥与去重逻辑不变

#### Scenario: 刷新后重新应用搜索

- **WHEN** 用户提交关键词后点击刷新重新拉取首页
- **THEN** 列表在搜索词下重新筛选展示（标题或 UP 主名称），搜索词保留

#### Scenario: 切页返回状态保持

- **WHEN** 用户提交关键词并已加载若干页后切到"设置"再返回在线历史
- **THEN** 列表与搜索词保留，按该词筛选展示，未重新拉取首页
