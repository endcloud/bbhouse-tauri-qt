# bangumi-ui Specification

## Purpose
定义"番剧"页面的 UI 行为契约：追番追剧两桶的标准服务端分页与四档 SelectorBar 客户端 season_type 过滤（番剧/国创/影视/纪录片）、竖向滚动且整体居中的等宽网格与竖版封面卡片 widget、卡片点击起播剧集（交由播放窗口剧集模式承接）、标题栏搜索当前页投影，以及浏览状态在导航切换中的帧缓存保持。

## Requirements

### Requirement: 数据源与追番追剧两桶标准分页

番剧页 MUST 通过 bilibili-api-client 的追番追剧列表端点拉取当前账号数据：服务端 `type` 参数仅区分**追番（type=1）**与**追剧（type=2）**两桶（实测口径：文档其余取值服务端拒绝）。页面 MUST 采用**标准服务端分页**（30 条/页，pn/ps 推进）：翻页 MUST 发起对应页请求；单页内容不足 30 条或已达响应总数时对应方向 MUST 禁用；单页内条目按 `season_id` 去重、保持响应顺序。桶数据 MUST 在会话内记忆当前页（页码、当前页条目与总数）：番剧与国创两档共享追番桶、影视与纪录片两档共享追剧桶——同桶两档间切换 MUST 对该桶当前页做纯重投影（零网络）；换桶首次进入 MUST 拉取该桶第 1 页。页面 MUST 按档位对条目做客户端过滤（服务端桶内 season_type 混合下发）：**番剧=season_type 1、国创=season_type 4、影视=season_type 2 或 5、纪录片=season_type 3**；其余类型（综艺等）MUST NOT 呈现于任何档位。页面 MUST NOT 落库任何数据。加载失败与登录失效 MUST 呈现本地化提示且保留既有页面内容可重试；目标桶该页过滤后为空且无搜索词时 MUST 呈现本地化空态提示（分页信息呈现"暂无记录"）。

#### Scenario: 首次进入番剧档拉第一页

- **WHEN** 用户首次进入番剧页（默认番剧档）
- **THEN** 页面请求追番桶第 1 页（30 条）并过滤出 season_type=1 的条目按响应顺序呈现，综艺等其他类型不出现，分页栏显示页码与总数

#### Scenario: 翻页发请求

- **WHEN** 番剧档第 1 页已呈现且用户点击"下一页"
- **THEN** 页面发起追番桶第 2 页请求并整体替换当前页卡片，页信息更新；末页时"下一页/末页"禁用

#### Scenario: 切档到共享桶零网络

- **WHEN** 追番桶第 3 页已加载，用户从"番剧"切到"国创"档
- **THEN** 页面直接对已加载的第 3 页条目按 season_type=4 重投影呈现（页码不变），不发起任何网络请求

#### Scenario: 影视与纪录片共享追剧桶

- **WHEN** 用户先在"纪录片"档浏览后切到"影视"档
- **THEN** "影视"档直接从追剧桶当前页按 season_type∈{2,5} 过滤呈现，不重新拉取

#### Scenario: 加载失败与空态

- **WHEN** 某页请求失败或登录失效，或某档当前页过滤后无任何条目且无搜索词
- **THEN** 页面呈现对应本地化失败/登录失效/空态提示，既有页面内容（如有）保留，重试重拉当前页

### Requirement: 冻结标题带与四档 SelectorBar

页面顶部 MUST 提供冻结标题带（沿用统一页面冻结标题带标准：高 56 DIP、边距 24 DIP、子元素垂直居中）：左侧大标题"番剧"，标题右侧为单 SelectorBar 四档——**番剧、国创、影视、纪录片**（恒有且仅有一档选中，默认番剧档），右侧仅图标刷新按钮（经宽度同步机制与网格右缘对齐）。切换档位 MUST 重置滚动到顶部并按该档投影呈现；刷新 MUST 重拉当前档所属桶的当前页（保旧卡整体替换，沿用在线历史页刷新语义）并重读当前生效凭据源（含调试双 Cookie 开关），刷新后已提交的搜索词 MUST 重新应用。列表滚动超过阈值时 MUST 呈现回到顶部悬浮按钮。

#### Scenario: 标题带构成

- **WHEN** 用户进入番剧页
- **THEN** 顶部冻结带内从左到右为大标题（zh-CN"番剧"/en-US"Bangumi"）、四档 SelectorBar（zh-CN：番剧/国创/影视/纪录片）与右缘对齐的刷新按钮，内容滚动时标题带保持冻结

#### Scenario: 切档重投影

- **WHEN** 用户从"番剧"档切到"纪录片"档
- **THEN** 列表切换为纪录片档条目并回到顶部，番剧档已呈现内容在其返回时保持

#### Scenario: 刷新保旧卡

- **WHEN** 番剧档已呈现条目且用户点击刷新
- **THEN** 既有卡片保持可见（不闪空白）且加载指示呈现，新数据到达后整体替换当前页内容并重新应用当前搜索词

### Requirement: 竖向滚动网格与竖版封面卡片 widget

页面内容 MUST 竖向滚动（横向滚动 MUST 禁用），当前档条目以**等宽等高、整体水平居中**的标准网格呈现（MUST NOT 使用瀑布流面板，MUST NOT 贴左对齐）：网格列数随窗口宽度自适应，网格块（含未排满的稀疏行）在视口内水平居中。每条目 MUST 使用为本页面重新实现的**竖版封面卡片 widget**（MUST NOT 复用横版 HistoryCard）：竖版节目封面（约 3:4 高宽比）为卡片主体，封面右下角 MUST 呈现评分角标（rating.score，条目无评分时该角标省略），封面下方为标题（单行截断）与副标（单行截断、次级色：观看进度文本优先，否则条目简介，均为空时副标行省略）。封面 MUST 按容器物理像素请求匹配的 CDN 转码图并随窗口 DPI 变化重推尺寸（沿用既有缩略图推送机制）。卡片 hover MUST 呈现可点击的视觉反馈。视图底部 MUST 呈标准分页栏（首页/上一页/下一页/末页与页信息，复用本地历史页分页资源键；加载中双向禁用）。

#### Scenario: 竖版卡片视觉契约

- **WHEN** 番剧档呈现某条目
- **THEN** 该卡片为竖版封面主体、封面右下角评分角标（如 9.8）、下方标题与副标两行，卡片以等宽列网格排布并随窗口宽度自动换行

#### Scenario: 稀疏网格居中

- **WHEN** 当前档当前页过滤后仅剩少量条目（如 3 张卡片）
- **THEN** 这些卡片以原尺寸排成一行并整体在视口内水平居中，不贴左对齐

#### Scenario: 竖向滚动无横向滚动

- **WHEN** 用户在条目多页的档位滚动浏览并调整窗口宽度
- **THEN** 内容仅竖向滚动（无横向滚动条），网格列数随宽度自适应换行，分页栏固定于内容区底部不随内容滚动

#### Scenario: 无评分与无副标条目

- **WHEN** 某条目响应内 rating 缺失且进度文本与简介均为空
- **THEN** 该卡片无评分角标、无副标行，标题仍完整呈现

### Requirement: 卡片点击起播剧集

点击竖版卡片 widget MUST 起播该节目：页面 MUST 经 PGC 剧集详情端点拉取该剧集全部分集（含每集 epid 与 cid），播放层 MUST 先确保单例播放窗口存在（未开则创建，已开则复用并激活到前台），随后进入**番剧剧集模式**起播（行为按 video-playback-window 规格的"番剧剧集模式与选集"执行）：起播分集 MUST 定位为该剧集云端最近观看的分集（响应自带 last_ep_id；无观看记录时第 1 集），集内位置沿用既有续播规则。剧集拉取或起播失败 MUST 呈现本地化提示且不影响页面浏览。卡片点击 MUST NOT 打开浏览器页面。

#### Scenario: 点击卡片起播未看过的番剧

- **WHEN** 用户点击一部无任何观看记录的节目卡片
- **THEN** 播放窗口被创建（或复用激活）并进入剧集模式，从第 1 集起播，顶栏出现选集菜单，右侧无播放列表面板

#### Scenario: 点击卡片续播看到一半的番剧

- **WHEN** 用户点击一部云端记录看到第 3 集的节目卡片
- **THEN** 播放窗口起播第 3 集，集内位置按既有续播优先级（会话 > 本地持久化 > 集内定位）处理

#### Scenario: 剧集拉取失败

- **WHEN** 点击卡片后剧集详情端点请求失败
- **THEN** 页面呈现本地化失败提示，播放窗口与当前播放不发生变化，浏览不受影响

### Requirement: 标题搜索

番剧页 MUST 接受主窗口标题栏搜索框提交的搜索词，对**当前档当前页已加载条目的标题**做不分大小写的子串匹配筛选展示（条目无 UP 主维度，仅按标题匹配，与本地历史页"仅当前页"语义同构，MUST NOT 跨页搜索未加载条目）；搜索 MUST 为已加载数据的即时投影，搜索提交本身 MUST NOT 发起网络请求、MUST NOT 触发翻页或桶拉取。投影为空且搜索词非空时 MUST 呈现本地化"未找到匹配"提示（含当前页已加载条数）。提交空词 MUST 恢复展示当前页全部条目。搜索词 MUST 为页面帧缓存的一部分：切页再返回时筛选效果保持，切档后新档条目按当前搜索词重新投影。

#### Scenario: 标题匹配投影

- **WHEN** 番剧档已全量加载且用户提交关键词
- **THEN** 仅渲染标题含该关键词（忽略大小写）的条目，搜索提交本身不发起网络请求

#### Scenario: 空结果未找到匹配

- **WHEN** 提交的关键词在当前档当前页条目的标题中无任何匹配
- **THEN** 列表呈现本地化"未找到匹配"提示（含已加载条数），不发起任何网络请求

#### Scenario: 清空恢复与切档重投影

- **WHEN** 用户清空搜索框提交后切到另一档
- **THEN** 原档恢复展示全部条目；新档条目按当前（已清空的）搜索词呈现全量

### Requirement: 帧缓存与浏览状态保持

用户从番剧页切换到其他导航菜单项再返回时，两桶已加载的当前页数据与页码、当前档位、已提交的搜索词 MUST 完整保持，MUST NOT 重新拉取；页面滚动位置 SHOULD 尽力保持但允许 XAML Frame 缓存限制导致的位置重置。

#### Scenario: 切页返回状态保持

- **WHEN** 用户在番剧页加载番剧档后切到"设置"页再返回
- **THEN** 页面仍处于番剧档并直接呈现已加载条目，不重新发起请求，搜索词（如有）保持

### Requirement: 港澳台独立标签

番剧页 MUST 增加“港澳台”标签，从全部已追番页筛选标题含“僅限港澳台地區”的条目，兼容简体和括号变体；MUST 按 seasonId 去重后每页 30 条本地分页。常规分类 MUST 排除这些条目。追番发现 API MUST 直连，地区详情与播放 API MUST 通过 regional-bangumi-proxy 能力路由。搜索 MUST 先过滤完整区域结果再分页，刷新失败 MUST 保留旧结果并允许重试。

#### Scenario: 区域番剧位于后续追番页
- **WHEN** 用户首次进入港澳台标签且该作品不在追番第一页
- **THEN** 扫描后续页后仍呈现该作品，区域页总数仅包含符合条件的去重结果

#### Scenario: 地区详情与起播
- **WHEN** 点击港澳台卡片或详情中的分集
- **THEN** 详情和播放解析携区域标记，普通番剧起播无该标记
