# 内存生命周期与后台页面回收（2026-09-20）

变更：`optimize-memory-lifecycle`。应用版本维持 2.0.2，本轮没有打包或发布远程版本，尚待用户 UI 手测。

## 使用行为

设置新增“后台页面保留时间”：1、5、10、30 分钟，默认 5 分钟，持久化并立即生效。调整时间会从调整时重新计时。

- 首次访问才创建页面，重选当前页不重建；阈值内切回保留搜索、页码、滚动等页面状态。
- 离开超过阈值，Loader 销毁页面，释放卡片/图片/局部模型，并清理相应控制器的可重建浏览缓存；返回时重新加载。超时后临时搜索、页码和滚动位置可重置。
- 个人空间也使用同样规则；在个人空间停留时，之前的一级页面进入后台倒计时。返回一级页面时若已过期则重建。
- 下载管理页面回收只销毁视图，下载任务和本地媒体目录仍由独立控制器维护；本地历史页销毁也不取消同步，返回时显示当前同步状态并加载列表。
- 当前可见页面不因窗口最小化或失去焦点被回收。独立视频/直播播放器不随一级页面回收停止。
- 未保存的设置草稿及管理弹窗内容属于页面临时状态，超时后可能清除；已保存配置、关注名单和用户数据库不受影响。

## 内存与指针处理

详细底层及 FluentUI 审计见 [指针与资源所有权审计](指针与资源所有权审计.md)。本轮在 QObject 父子所有权、独占 RAII、受限缓存和安全异步回投基础上修改，没有对已正确借用的裸指针统一套智能指针。

| 范围 | 实现 |
| --- | --- |
| 一级页面和个人空间 | `ExpiringPageLoader` 控制后台 Timer；到期 `active=false`，八类浏览控制器提供 `releasePageCache()`。 |
| 浏览异步请求 | 清理时递增 generation，晚到的列表/资料/分区/详情请求不能重新填充缓存或重置新请求 busy；控制器销毁后 watcher 自动断开回投。 |
| 特别关注 | 后台任务独立持有存储对象；保留应用级名单与保存队列；最多保留 12 个 UP 浏览会话。 |
| 流行/番剧 | 流行内容选择、番剧详情分别最多保留 12 份最近使用缓存；流行独立整季详情也受此上限约束。 |
| 头像 | 内存元数据最多保留 512 项；七天磁盘缓存和在途请求去重保留，不删除用户头像缓存。 |
| 本地历史/服务管理 | 访问控制器成员的任务使用所属线程池，在析构体内等待，历史同步先设置取消标记。 |
| 点播控制器 | 访问自身/Store 的任务迁入最多 4 线程的所属池，析构先等待；关闭释放播放列表、源快照、候选和清晰度。 |
| mpv 回调 | 队列回调同时检查原客户端寿命，避免已替换内核回调误访问；共享 handle、渲染 context、FBO 与 Qt renderer 的既有所有权保留。 |
| 弹幕 | 清空时释放 sprite CPU 图像缓存与两套源条目容量；合并 future 取走结果，合并输出收紧容量；seek 仍复用缓存。 |
| 图片 | 普通卡片解码尺寸限定 400×225（也覆盖本地图片）；原图预览关闭/随页面隐藏时解除 source，避免隐藏层持有大图。 |
| 资源释放 | 修复 PIMPL、数据库失败连接、二维码每次重绘、树节点、图线、翻译器、单例、原生 DLL/CF 资源及壁纸工作线程的所有权问题。 |

仍保留 Qt 图片/字体缓存、渲染器共享所有权和 mpv 缓冲/硬解设置，以免引入频繁重解码或播放退化。用户长时间持续浏览当前动态/在线历史页时，其当前浏览池仍按既有分页契约增长；离开超时后回收。下载记录属于持久业务状态，不因页面超时丢失。

## 非交互验证

- macOS Qt 6.11.2 Release 构建应用及全部 regression-tests。
- `page-lifecycle`：真实 QML Loader 首访、短时往返、当前页不超时、到期 QObject 真实析构、重建、阈值修改和重复回收。
- 浏览控制器：释放后旧结果拒收、重新加载、关注名单保留、12 份缓存上限、512 项头像元数据与磁盘缓存复用；后台工作结束前销毁 owner 后回调不执行。
- 播放器与弹幕：真实 libmpv 延后回调取消、连续销毁控制器、weak_ptr 证明 sprite 图片和合并结果释放，20,000 条弹幕折叠后不保留原始容量。
- 资源：32 次失败数据库打开不增加注册连接，128 次树数据替换后旧节点不存活，空树回收及共享单例所有权。
- 测试只使用 build 内隔离数据与离线/loopback fixture；没有注册真实服务或读取真实观看数据。UI 不进行自动交互验收。

最终结果：macOS Release 应用及全部 `regression-tests` 构建成功；CTest **43/43 通过**（65.72 秒，包含真实 libmpv 与 macOS 离屏 OpenGL 回归）；OpenSpec 严格校验及 `git diff --check` 通过。第一轮发现的流行缓存第 13 项边界已修复并在最终全量回归通过。

## 手测清单

1. 设置为 1 分钟，在动态、本地历史、特别关注、番剧、流行、直播、下载、设置与关于间往返：一分钟内保持页面，一分钟后重建。当前页停留超过一分钟仍不刷新或丢失状态。
2. 在列表加载或分区补查时切走并等超时，再进入；不应出现过期数据、永久 busy 或重复卡片。同一作者空间过期后重新打开应显示作者资料。
3. 下载/历史同步开始后切到其他页超过一分钟；后台任务应继续，返回显示真实进度。独立视频/直播播放应连续。
4. 打开原图预览后关闭或切页，再返回时遮罩不残留；检查封面和本地图片的清晰度。
5. 连续开关播放器、切片、切换弹幕实现，确认画面、声音、字幕、弹幕和系统媒体控制正常；正在请求时直接退出应安全完成。
6. 使用活动监视器/任务管理器记录启动、遍历页面、等待回收、重复几轮后的内存趋势。比较稳定平台而非单次瞬时值；Qt/GPU/分配器可能保留可复用内存，不能要求 RSS 立即同比下降。
7. Windows 需额外检查自绘窗口命中测试、热键、退出及服务管理；macOS 检查普通窗口和全屏的播放器反复打开关闭。

## 验证边界

静态审计覆盖应用的分配/释放、异步捕获和原生资源入口，以及实际内嵌 FluentUI 包装层；第三方 Qt、mpv、驱动及图表/二维码算法内部没有逐路径证明零泄漏。本轮不报告未经实测的内存降幅，未执行真实账号长时间 Instruments/ASan/LSan；Windows 原生执行和 UI 仍待用户验证。OpenSpec 保留活动 change，手测通过后再同步归档。
