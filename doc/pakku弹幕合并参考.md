## 本项目规则

入口：`DanmakuFilter::mergeSimilar(const QVariantList &entries)`，无 QObject、字体对象或全局可变状态，可以在后台线程运行。必须传入原始数据，不能把已经加了数量后缀的结果再次作为原始数据处理。

真实输入字段为 `time`（秒）、`type`、`message`、`fontSize`、`fontColor`。结果保留首条完整 map，额外提供 `mergeCount` 和 `mergeOriginalMessage`；数量超过 1 时，`message` 为原始文本加 ` ×N`。原始列表保持不变，关闭合并后可完整恢复。不能在绘制帧循环内调用。

1. 按有效时间稳定排序，同一时间保留输入先后顺序。每组时间窗为**首条起 10 秒，含边界**；后续重复不延长时间窗。
2. 仅合并相同 `type`（1～5）。滚动、顶部、底部等不同模式彼此隔离，不改变位置语义。
3. 比较文本采用 Unicode NFKC、大小写折叠、空白折叠、汉字间空格移除及结尾标点移除。纯标点文本不清空；`???` 与 `!!!` 保持不同。规范化只用于比较，屏幕保留首条原文。
4. `666…` 和 `233…` 视为惯用重复表达；不把任意数字中的重复数字压缩，例如 `1000` 与 `10000` 不合并。
5. 规范化后完全相等时直接合并。否则，短于 6 个 Unicode 码点的任一文本禁止模糊合并；6～11 码点至多允许 1 次增删改，12～128 码点至多允许 2 次。使用窄带 Levenshtein，保持字符顺序，不用无序字符计数代替距离。数字序列不同的文本不做模糊合并。
6. 模糊候选始终与首条代表文本比较，避免 A≈B、B≈C 导致 A 与差异很大的 C 被连锁吞并。不会做拼音、语义、跨模式合并或字体放大。

这是保守的文本近似判定，并非语义理解。长句中关键字变化仍可能被当作近似表达，用户可关闭合并；不同数字、不同短句受到额外保护。

## 计算与内存边界

- 时间窗内最多维护 1024 个候选组与对应精确匹配键；超过后淘汰最早候选，原输出仍保留。
- 每条最多检查最近 32 个组做模糊比较，每次最多比较 128 个 Unicode 码点；距离阈值最高为 2，每行至多计算 5 个距离单元。
- 超过 512 个 UTF-16 单元的原始文本直接保留，不参与合并。无效时间、空白文本、未支持模式也不强行合并，后续已有布局校验负责是否绘制。
- 排序为 O(n log n)，此后每条计算量有固定上限；总输入与输出仍需要 O(n) 内存。密集流中较老、被淘汰的相似项可能不合并，优先确保处理不会随候选量平方增长。
- 合并不会修改样式、时间或用户数据库；不接触网络、用户凭据，也没有远程服务依赖。

## 非交互验证

`tools/danmaku_filter_test.cpp` 覆盖无序输入、首条样式保留、输入不可变、10 秒边界、非滑动窗口、模式隔离、Unicode/标点/空格、短句和 emoji 防误合并、数字保护、字序、增删改距离、非传递归并、无效/超长输入、密集流淘汰及并发调用一致性。

本机 Qt 6.11.2，独立 Release 编译实测（仅作为量级记录，不使用易抖动的计时阈值作为断言）：

| 输入 | 结果 | 耗时 |
|---|---|---|
| 同时出现的 20,000 条完全重复 | 1 条，`×20000` | 约 17 ms |
| 同时出现的 20,000 条不同编号 | 全部保留 | 约 20 ms |
| 4,000 条长公共前缀、长度 128 的模糊近似但不匹配文本 | 全部保留 | 约 288 ms |

这些数据不代表 UI 帧率或 Windows 性能。设置开关、起播、seek、切片以及两种渲染实现的实际观感由用户手测。
