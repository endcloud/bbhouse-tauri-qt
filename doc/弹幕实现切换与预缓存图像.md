# 弹幕实现切换与预缓存图像

> 验收更新（2026-09-18）：用户确认手测完全通过。下文“待手测”描述保留为交付时记录；本次 OpenSpec 清理记录见 [归档审计](OpenSpec积压清理与遗留差异.md)。

2026-09-18。上一版场景图实现已由用户确认功能可用，但实际播放仍不够流畅，起播和 seek 有抽动。本次保留原方案，新增可对比的 Qt 图片缓存实现。真实视频流畅度、Windows 字体及跨屏观感待用户手测。

## 使用方式

进入 **设置 → 播放与弹幕 → 弹幕实现**：

| 选项 | 保存值 | 行为 |
| --- | --- | --- |
| 场景图文字 | `scene` | 默认，保留原 QSGTextNode 方案及历史在屏重建行为 |
| 预缓存图像 | `sprite` | 提前生成文字图片、复用纹理移动；seek 从目标位置之后开始，不补播之前的弹幕 |

选择立即应用并自动保存，重启恢复。切换会清空并重建弹幕层；视频位置、暂停、倍速、音量及弹幕开关不变。暂停时切到新实现，若当前时刻没有新弹幕，画面可能暂时没有弹幕，继续播放后按时间进入。

## Qt 实现

- `DanmakuSpriteLayout`：独立调度器，滚动/顶部/底部弹幕、滚动车道防追尾、按时间二分定位。提前 2 秒准备文字；最多迟到 250ms，稍晚就绪从边缘入场，已错过的条目跳过。
- `QTextLayout + QPainter + QImage`：后台一次性排字、描边、文字抗锯齿；保留 PingFang SC / Microsoft YaHei 平台默认字体及字体回退。图片按窗口 DPR 生成，缩放与字号变化使旧准备结果失效。
- `DanmakuEngine`：`scene` 保持原文字节点路径；`sprite` 只更新图像节点位置，正常小幅 mpv 采样不会改变在屏速度。暂停/缓冲冻结单调动画时钟，恢复不累计等待时间；显式 seek 重置。若检测到超过 2 秒的非显式时间不连续，仍会重新同步。
- 起播/seek：先隐藏旧弹幕，隔离旧位置采样，收到当前 mpv 条目的 `PLAYBACK_RESTART` 且内核不再 seeking 后释放时钟。位置检查包含事件排队经过时间及倍速，覆盖延迟处理；控制器显式请求精确 seek。
- 生命周期：每次失效递增 generation，后台通过共享结果信箱投递；旧任务不能更新新场景。销毁弹幕层不等待线程池。纹理创建/销毁均在 Qt 场景图线程完成。

资源预算：后台最多 4 项（旧 generation 未完成任务及未收取结果也计数），CPU 缓存最多 256 张 / 16 MiB，单张最多 2 MiB，在屏最多 128 条，每帧最多上传 4 张。重复文字共享 CPU 图像，GPU 节点按在屏项持有纹理；显存不是固定 16 MiB。极密集或超预算内容会跳过，优先避免突发积压。暂停时仍排空后台任务和分批上传队列。

顶部截图沿用 mpv 异步 `screenshot-to-file … video`，不抓取 Qt 窗口，因此两种弹幕实现都不进入视频截图。

## 手测要点

1. 对同一条弹幕密集视频分别选择两种实现，播放中切换、关闭播放器再打开、重启应用；确认选项记忆和视频状态不变。
2. 冷启动、恢复历史位置、切分 P、切清晰度、连续前后 seek；重点观察新实现有无回跳、补发一大群旧弹幕、长期不出弹幕。短暂留白属于前向调度行为。
3. 暂停时 seek 再恢复，连续拖动进度条，小幅 seek；观察旧弹幕是否立即清除，等待时间是否造成恢复后的位移跳跃。
4. 测试 0.5× / 1× / 2×，以及暂停、网络缓冲、恢复；连续播放较长时间，检查弹幕与内容同步和速度变化。
5. 同时检查滚动/顶部/底部、短句/长句/中英混排/表情；设置字号、范围、透明度、速度及开关，关注描边、车道间距和字形。
6. Retina 与外接屏间移动窗口、缩放窗口、切换全屏；分别观察 macOS 苹方和 Windows 微软雅黑的平滑度、图片清晰度及是否残留旧层。
7. 有弹幕时点击播放器顶部截图按钮，检查保存图片只有视频内容；确认播放与控制面板仍正常。
8. 快速切换实现、换片、关闭窗口并重新打开；检查崩溃、持续高 CPU 或内存持续增长。发现问题请记录实现选项、视频/分 P、时间点、倍速和显示器刷新率。
