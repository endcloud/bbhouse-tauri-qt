# 播放状态与窗口布局修复

2026-09-18，OpenSpec：`fix-player-state-and-window-layout`。本次处理用户报告的三处问题，实际窗口观感待用户手测。

## 修复内容

1. **新窗口首次起播的播放/暂停图标**：PlayerController 初始 `paused=true`，mpv 默认 `pause=false`，MpvClient 原先用 `lastPaused=false` 去重，导致首次通知被吞掉。现在转发初始属性快照，媒体装载时也读取并发送实际暂停状态，由控制器自身去重。没有把起播强制假定为播放；暂停/恢复仍以实际内核状态确认。
2. **播放列表长文字**：封面与文字区改为明确锚定，标题占剩余宽度、最多两行省略，说明单行省略并将换行折为普通空格。两者均用纯文本，文字区域有高度和裁剪边界，不让类似 HTML 的标题改变布局。
3. **主窗口按钮顶部间隙**：48px 标题栏中原来的 30px 按钮垂直居中，上下各空出 9px。内嵌 Qt6 FluentUI 的最小化、最大化/还原、关闭按钮现在随标题栏高度铺满；宽度与图标大小不变。macOS 原生红绿灯继续由系统管理；Windows 最大化原生边框补偿未改。

## 验证

- 本机 Qt 6.11.2 Release/Debug 构建通过，CTest 9/9 通过。
- 真实 libmpv 回归：新内核首次默认播放通知、file-loaded 前同步实际状态、第一次操作暂停、第二次恢复、同一内核状态未变时新媒体仍刷新界面状态。
- 此前音频 fixture 的“暂停 seek”描述不准确：`loadSingle` 会清除 pause；本次显式覆盖暂停/恢复后，以播放中的精确 seek 验证重启事件及目标位置。音频专用 `ao=null` 在暂停 seek 时不保证立即发出 `PLAYBACK_RESTART`，不将这个测试当作暂停视频解码行为的证明。
- 主窗口、播放器、设置页离屏装载通过，无 QML 类型/绑定错误。
- 临时 Qt Quick 几何检查从实际 PlayerWindow 提取 delegate，并加载实际 FluentUI 控件：300px/240px 列表宽度下，长中文、连续英文、类似 HTML 的标题与多行说明均显示省略、遵守行数且不越界；标准按钮 y=0、高度=48。过程中发现并去掉了标题 `implicitHeight` 的循环依赖，最终无绑定循环。

- OpenSpec 严格验证与 Git diff 检查通过。上述离屏几何检查不替代 Windows 原生窗口行为手测。
