# 播放器、页面、下载与更新修复（2026-10-13）

本次对应 OpenSpec change：`improve-player-pages-downloads-update`。

## 已实现

- Windows 视频/直播播放器进入全屏前移除原生标题栏和边框，退出后延迟恢复；视频播放器支持普通视频分 P选择。
- 特别关注按加入时间倒序，修复直接点击页码后的分页状态，增强头像选中态；个人空间改由主窗口统一 Fluent 返回按钮和路由栈承载。
- 下载按 `videoKey` 去重；视频任务视为已含音轨，重复的仅音频任务自动忽略；点播清晰度持久化，默认 1080P（80），缺失时回落最近较低档位。
- 历史搜索使用 `/x/web-interface/history/search` 的 `pn/keyword/business=all` 参数，并隔离搜索竞态。
- 直播使用 mpv `stream-record` 属性录制，并复用截图压缩管线的帧截图；录制文件直接写入下载目录下的 `live/`，命名为 `live_<主播>_<时间戳>.mp4`，不再按每次录制创建子目录或包含直播标题。截图继续按场次写入图片目录下的 `live/live_<主播>_<时间戳>/`。
- 启动异步请求 `https://cos.endcloud.cn/bbhouse-qt/version.json`；本地 `version-code` 缺失时使用 10，仅远端更高且 URL 合法时显示更新弹窗。
- 鼠标侧键/系统 Back 键触发统一返回；Windows 首个 XInput 手柄映射到播放器播放、返回、全屏、音量和进度控制。

## 构建与回归

使用 Qt 6.11.1 MinGW 预设构建 `BBHouse.exe` 及相关测试目标。以下 9 项通过：

`api-regression`、`player-runtime`、`special-follow-page`、`online-history-controller`、`live-player`、`player-controls`、`download-page`、`download`、`download-cover`。

另外，`openspec validate improve-player-pages-downloads-update --strict` 和 `git diff --check` 通过。

本轮录制细节回归：主程序和 `live-player-test` 重新构建成功。WAV 使用受限预读的真实 mpv 录制，确认停止、切房、关闭后文件含媒体数据且 RIFF 长度完成回填；设置 `BBHOUSE_LIVE_TEST_FFMPEG` 后，以本地生成的 H.264/AAC 测试源实际录制 MP4，手动停止、切房、关闭窗口对应控制器入口及销毁控制器四种输出均通过 FFmpeg 双轨完整解码。未用手工创建的输出文件替代录制结果，测试文件位于项目 `.tmp/` 并自动清理，未操作用户下载目录。

录制中停止图标采用红色 `#ff4d4f`。录制保留原流压缩编码并封装 MP4，不二次编码。mpv 解复用线程异步收尾，因此文件校验在后台最多等待 5 秒，不阻塞窗口关闭；容器结构检查不等同于逐帧解码，正常退出应用也会先停止录制，强制终止进程或断电不在此保证范围内。

## 实机验收与后续

用户于 2026-10-13 在目标环境反馈整体“基本 pass”，Windows 全屏/Windows 键/鼠标侧键/Xbox 输入、直播截图和更新提醒均通过基础验收。直播录制启动问题已改用 `stream-record` 属性并在后续复测中确认可用。

上一轮复测显示 `record-file` 返回 `-4 invalid parameter`。核对 mpv 手册后确认录制入口应为运行时 `stream-record` 属性，而不是 `record-file` 命令；停止、切换直播/线路、播放异常和关闭窗口都会先清空该属性，再后台检查 MP4 的 `ftyp/moov/mdat` 结构或 WAV 的 RIFF 长度。收尾失败会记录路径和错误，主动停止时通过弹窗报告；窗口关闭时不打断关闭流程。录制文件直接写入 `live/`，名为 `live_<主播>_<毫秒时间戳>.mp4`，存在同名文件则追加序号；以正斜杠路径传给 mpv、以 Windows 原生路径显示。启动失败提示仍会显示错误码、mpv 错误文本、录制目录和目标文件路径，诊断不包含直播流 URL 或凭据。该 OpenSpec change 暂不归档，等待用户复测真实直播切换和直接关闭窗口。
