# 指针与资源所有权审计（2026-09-20）

本记录覆盖本轮核心服务、下载、偏好设置和内嵌 FluentUI 的审计；页面控制器、播放器及页面超时释放的修改与整体验证见[内存生命周期交付记录](内存生命周期与后台页面回收.md)。审计优先使用项目 CodeGraph 定位所有权，再复核实际编译源码。静态审计不等于已经证明所有平台零泄漏。

## 已修复

| 范围 | 问题与处理 |
| --- | --- |
| AppPreferences | `Private *d` 没有释放；改为 `unique_ptr`，析构在实现文件定义，连同 QSettings 一起释放。 |
| DownloadStore | SQLite 打开失败时构造函数抛出，析构不会执行，命名连接遗留在 Qt 注册表；失败路径先重置数据库句柄再移除连接，禁止连接 RAII 对象复制。 |
| BilibiliApiClient | 线程控制对象跟随工作 QObject 移入自己的线程，退出只等待 3 秒且随后可能从外线程销毁网络对象；现在线程控制对象独立持有，先在网络线程清理网络子对象并迁移回销毁线程，再 quit/wait/join。所有请求调用者仍须先收尾；主程序已有线程池退出等待。 |
| FluQrCodeItem | 每次重绘的 QRcode 缺少 `QRcode_free`；改为带自定义释放器的 `unique_ptr` 并检查编码失败空指针。 |
| FluTreeModel | 刷新仅删除根节点，其他节点挂在模型下越积越多；节点统一由根所有，reset 先通知视图再释放旧树，折叠节点仍可展开复用。 |
| FluentUI 单例 | 无 parent 且静态裸指针可能被 QML 引擎销毁后悬空；统一采用 QPointer、应用 QObject 所有权及明确 CppOwnership。 |
| FluApp | 多次 init 累积翻译器；替换前先卸载并释放旧对象。 |
| FluHotkey | 热键与捕获包装对象的回调原绑定 qApp；现由包装对象持有，回调 context 同步随包装对象失效。 |
| BasePlot | 删除 Graph 包装器没有删除 QCustomPlot 内部图线及数据；同时移除实际图线。 |
| FluFrameless | Windows 两处 LoadLibrary 缺 FreeLibrary；补齐，且命中测试先检查 item 是否仍有 window。 |
| macOS QHotkey | 在使用键盘布局借用指针前提前 CFRelease 所有者；增加作用域守卫，使所有查表及提前返回路径均正确释放。 |
| FluTheme | 后台任务捕获 this 无等待且跨线程修改 QFileSystemWatcher，壁纸查询慢时每秒继续排队；改为无 QObject 依赖的静态路径查询、一个在途任务、私有线程池析构等待，结果以带 context 的队列调用回 GUI 线程更新。 |

## 核实的既有所有权

- 核心 API 域模块使用值类型 JSON/容器；公共网络请求的成功、错误和超时路径均 deleteLater reply，QNetworkAccessManager 作为最终父对象回收兜底。请求级代理客户端在创建线程内使用和销毁。
- HistoryStore 各操作通过作用域守卫释放 QSqlDatabase，并在移除连接前先结束 query 和清空句柄；打开失败已有显式移除。
- AvatarCache 由应用持有，reply 完成删除、信号有 context；字节缓冲使用共享所有权，QImage 解码有限尺寸和最大下载大小。本轮头像元数据另增加 512 项上限；未做磁盘缓存删除或改变七天有效期。
- DownloadController 的后台写入和封面提取捕获值快照，共享取消标记有明确寿命；watcher 有父对象且完成后 deleteLater。析构会取消并等待下载、封面及写库线程池，不会在后台继续使用已释放的控制器。
- 下载 worker/封面 worker 的 QProcess、QFile、QSaveFile 等栈对象自动回收；取消及失败清理遵循原下载临时文件授权边界。
- Windows 服务/计划相关正常路径中的 HANDLE、COM 初始化与系统错误缓冲具有配对关闭；本轮未安装服务、注册任务或改变真实数据库、ACL。
- 内嵌绘图事件经 postEvent 转交 Qt 所有；QCustomPlot 内部图元/轴由容器或 Qt 父对象释放，BasePlot 自身释放底层 plot。二维码 C 实现及图表库包含大量内部指针，本轮核对入口/出口与封装所有权，没有对第三方算法做逐分支形式验证。

## 自动验证与边界

- `download` 新增 32 次故障打开，验证失败后 SQL 连接注册表大小及内容不变；所有路径均为 build 内临时目录。
- `fluent-ownership` 检查折叠/展开复用、模型重置顺序、128 次数据替换后节点数有界、清空释放和单例应用所有权。
- `api-proxy` 的 loopback fixture 同时覆盖请求级与共享客户端，进程结束正常；`preferences` 覆盖偏好读写。以上四项均通过。
- 实际内嵌 FluentUI macOS Qt 6.11.2 编译通过。Windows 原生 DLL/句柄路径只做静态审查，未在本机执行；没有触发真实壁纸查询或 osascript，也没有调用真实 B 站 API。
- 这些检查验证具体资源所有权与回归行为，并未执行全应用 ASan/LSan 或 Instruments 长时间真实账号分析。Qt 图像缓存、GPU 驱动和系统分配器可能保留可复用内存，页面释放不保证 RSS 立即等量下降。
