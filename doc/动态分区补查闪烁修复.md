# 动态视频分区补查闪烁修复

对应 OpenSpec：`fix-dynamics-zone-flicker`。

## 原因与修改

每个视频分区补查返回后，`DynamicsController::applyZoneResult()` 更新池并调用 `reproject()`，原先无条件发送整个 `QVariantList`。卡片 `Repeater` 会把它当成替换模型，销毁并重新创建全部卡片、封面和布局；下一次查询又重复一次。分区按钮也绑定整个池，每个回应都会重新计算数组并重建按钮。

现在使用 `DynamicCardModel`（Qt `QAbstractListModel`）驱动卡片：

- 以完整 64 位视频 aid / 非视频动态 id 识别卡片。分区字段变化仅发对应行的 `dataChanged`。
- 指定分区下的新命中项只插入一张卡片；移除和重新排序使用行级通知，保留其他卡片实例。
- 去重代表换成更早投稿时仍按视频 aid 复用卡片；移动后重新计算瀑布流位置。
- 分区集合独立发通知，新分区追加、消失分区删除。QML 用 ListModel 增量维护按钮，已有按钮顺序与选择保持。
- 刷新成功后一次发布新投影，不再先发空列表。真正空结果仍正常清空。

当前 Qt 代码分区查询使用同一 `x/web-interface/view` 接口的 **aid 参数**（`fetchViewByAid`）。本次无需更换为 bvid；修复发生在查询结果到 UI 的更新链路。保留原有串行节流、会话缓存、分区解析规则、分类/搜索与续载逻辑。

上述回归不替代真实在线 UI 观感或 Windows 手测。增加新分区导致筛选行换行时，内容区自然下移仍是预期布局变化，不是卡片重建。

## 手测要点

1. 重启后进入“动态 → 视频 → 全部分区”，在分区仍逐条出现时观察卡片：封面和文字不再每隔一次请求闪空；滚动、悬停与打开的右键菜单不因无关分区回应重置。
2. 分区解析期间选一个已有分区，再叠加搜索；新命中卡片应渐进出现，已有卡片保持，当前分区选择不丢失。
3. 滚动续载、刷新、切换其他分类后回到视频、切页再回来；检查顺序、去重次数、搜索、分区筛选与加载状态仍正确。刷新成功时不应先出现整页空白。
