# 全平台应用图标导入（2026-09-19）

OpenSpec：`add-platform-app-icons`。用户提供的图标已导入 `app/resources/icons/`，构建不依赖项目外素材目录；macOS PNG/ICNS 根据 Dock 尺寸反馈增加透明留白，原始 macOS PNG 保存在 source 子目录。项目外原始文件未修改。

## 接入位置

- **通用运行时**：Qt 应用默认窗口图标与 FluentUI 默认窗口图标都已设置，关于页替换原 History 字形占位。主窗口标题栏仍沿既有布局隐藏图标，不占搜索空间；无头历史同步和服务 worker 不初始化 GUI。
- **Windows**：CMake 将 ICO 以原生 RC 资源编入 `bbhouse-qt.exe` 和 `bbhouse-history-service.exe`。MinGW/MSVC 共用模板，ICO 路径由 CMake 固化；deploy/发布目录复制 exe 时自然携带图标。
- **macOS**：GUI 运行时使用透明圆角 PNG；打包脚本将 ICNS 放到 `.app/Contents/Resources/icon.icns`，并设置 `CFBundleIconFile`。签名前、原包冒烟及迁移后冒烟检查声明、ICNS 格式与源资源一致性。已有旧 .app/DMG 需要重新打包才能包含新图标。
- **Linux**：Qt desktop ID 为 `io.github.endcloud.bbhouse-qt`，提供同名 `.desktop` 入口和 `hicolor/1024x1024/apps` PNG。安装组件仅提供桌面资源，不承诺完整 Linux 依赖打包。

## Linux 桌面资源安装

在 Linux 上完成 CMake 配置后，可执行：

```sh
cmake --install build --prefix ~/.local --component DesktopIntegration
```

确保 `bbhouse-qt` 可从桌面会话的 PATH 启动，且 Qt、FluentUI、libmpv 等运行库已由发行环境配置。桌面入口 Exec/TryExec 使用 `bbhouse-qt`，Icon 使用与 Qt desktop ID 对应的名称。图标与入口分别安装在 prefix 的 `share/icons/hicolor/1024x1024/apps/` 与 `share/applications/`。

代理负责构建、资源格式和打包逻辑、隔离回归检查；不操作真实账号或系统服务。本次不重新制作完整 DMG。

- Windows：重新构建后检查资源管理器 exe、任务栏、Alt+Tab 及关于页；原生服务 helper 的 exe 同样有图标。

## macOS Dock 图标偏大修复（2026-09-19）

用户截图显示图标比相邻系统应用大一圈。原 macOS PNG 的非透明边界覆盖整张 1024×1024 画布，缺少外围留白；只做圆角不能约束 Dock 中的视觉大小。

- 将完整图案缩至 824×824，置于 1024×1024 透明画布中央，四边各留 100 像素。macOS 运行时 PNG 和全部 ICNS 尺寸同步处理。
- 保留原图，新增 `scripts/generate-macos-icon.py`，避免日后重复缩小；Windows/Linux 素材保持原样。
- 检查 PNG 非透明边界为 `(100, 100, 924, 924)`；ICNS 解包后十个尺寸表示均含对称留白，1024 表示与运行时 PNG 逐像素一致。256 图标主体不透明边界为 `(26, 26, 230, 230)`，与本机 App Store 同尺寸图标一致。
- 重新构建的开发程序退出后再启动即可加载新资源；已打包的旧 `.app/DMG` 需重新打包。Dock 最终观感已由用户确认通过。
- 修复后验证：应用及回归目标构建通过，CTest **41/41**、OpenSpec 全量严格校验 **30/30**、差异检查通过，生成和解包验证的临时目录已清理。
