# 发布前持久化与隐私审计

日期：2026-09-19。对应 OpenSpec change：`prepare-public-release`。

## 结论与范围

审查了应用与内嵌 FluentUI 的文件、设置、SQLite、缓存、截图、任务调度和日志入口，并扫描 Git 当前追踪文件与所有本地可达历史 blob。未发现被追踪的 Cookie 文件、用户数据库、历史导出、特别关注名单、运行日志、私钥或命中规则的真实访问凭据/媒体签名。

审计没有打开本机实际 Cookie、设置文件、观看数据库或缓存，没有启动真实账号同步、注册系统任务或更改用户配置。源码中描述本机开发环境的用户名/绝对路径，以及 Git 作者姓名/邮箱，属于另一类公开元数据；它们不等于认证凭据，历史提交也没有为本次发布做身份匿名化或重写。用户已明确选择保留这些开发元数据。

初次扫描覆盖 **847 个追踪文件、1208 个历史 blob，规则命中为 0**。这是一项静态审查与规则扫描结论，不表示能从任意文件中识别所有个人信息。本次最终暂存后复扫 **877 个追踪文件、1208 个历史 blob，规则命中仍为 0**。发布前应重跑下述命令。

## 持久化清单

| 入口 | 内容及位置 | 隐私判断 |
| --- | --- | --- |
| `AppPreferences` | 用户级 `shizi/bbhouse-qt.ini`，语言/主题/播放器偏好、区域代理类型/主机/端口/用户名 | 用户设置不应随代码或二进制发布；代理密码只在内存，不写入 INI |
| `AppPaths`、`BilibiliApiClient` | 用户提供的 `bilibili.cookie.txt`；从可执行文件位置向上查找，最多四层 | Cookie 只读，用于请求；不自动复制到数据目录、数据库或系统任务 |
| `HistoryStore` | AppLocalDataLocation 或显式 `BBHOUSE_DATA_DIR` 下 SQLite、WAL/SHM、同步锁 | 包含真实观看时间/进度、作品/作者、历史 API 原始响应、游标、播放续播位置和同步结果，均属用户数据 |
| `HistoryStore::exportJson` | 同目录 `bilibili-history-export.json` | 主动同步成功后的本地导出，含真实观看记录，禁止随发布包或问题报告上传 |
| `SpecialFollowStore` | 数据目录 `special-follow.json` | UP UID、名称、头像 URL、添加时间可反映关注关系，属于用户数据 |
| `AvatarCache` | 数据目录 `avatar-cache/`，SHA-256 UID 文件名、PNG 与刷新时间 | 文件名哈希不代表匿名化；头像像素仍可识别关注对象。网络地址只在内存，头像七天刷新 |
| `HistoryScheduler` | 数据目录 `history-service.json`、当前用户 LaunchAgent 或 Windows 任务 | 保存绝对路径与计划；不含 Cookie 正文。服务配置使用原子保存与仅所有者读写权限；任务参数只传配置路径 |
| `ScreenshotWriter`、封面下载 | 用户图片目录内截图、`bilibili_cover/` | 用户主动保存的图像；截图临时原图随处理清理，均不进入构建打包目录 |
| mpv | 音视频缓冲与 API 地址在内存，截图显式保存 | `config=no`、`terminal=no`；已移除 `BBHOUSE_MPV_LOG` 原生日志落盘开关，避免 Cookie/媒体 URL 被内核诊断记录 |
| API 异常、同步审计 | UI 错误消息和 SQLite `sync_runs.message` | 新增统一诊断脱敏，移除 URL、Cookie/Authorization 请求头与常见 B 站认证字段后才显示/持久化 |
| 内嵌 FluentUI | Windows 系统版本读取、文件工具、控件诊断 | QSettings 入口只读取系统版本；未发现独立账号、Cookie、网络缓存或后台日志持久化 |
| 系统媒体控制 | 操作系统展示当前标题、作者、封面、播放状态 | 属于用户可见的系统媒体集成；应用内封面只做内存缓存，不创建额外历史日志 |

本地历史保留原始历史 API 数据是现有功能约定，并非遥测上传。Cookie 认证头不属于这些历史响应；播放器取流响应与带签名媒体 URL 未进入历史存储。操作系统、Qt 自身缓存、崩溃报告和用户手动保存的截图不应被当作可公开的诊断材料。

## 本次修补

- `.gitignore` 补充 Cookie 备份、SQLite/DB 及边车、历史 JSON、特别关注/计划配置、头像缓存、用户 INI、日志、环境文件与私钥容器。已有文件是否被追踪仍通过 Git 审计检查，不能依赖忽略规则移除已追踪数据。
- 移除 mpv 原生日志开关，并关闭内核文本消息。过去文档中的 `BBHOUSE_MPV_LOG` / `BBHOUSE_MPV_LOG_LEVEL` 调试方法不再生效；结构化播放错误仍保留。
- `ApiError::message()` 与 `what()` 统一脱敏。普通错误文字、API/HTTP 错误码保留，不把服务器回显的签名 URL 或认证信息写入同步审计。
- 提供只读脚本 `tools/privacy_audit.py`，只输出命中类别、路径和 Git 对象缩写，绝不输出命中的原始内容，不跟踪符号链接到项目外数据。

## 验证

```sh
python3 tools/privacy_audit.py --history
ctest --test-dir build -R '^(api-regression|player-runtime)$' --output-on-failure
```

两个相关目标已重新构建，CTest **2/2 通过**。新增回归覆盖 API 异常中的 URL/认证脱敏，以及继承原日志环境变量时真实 libmpv 不创建日志文件。测试仅使用项目 build 内临时文件、合成 Cookie 文本、本地静音 WAV 和 loopback HTTP fixture，临时目录自动清理。

`git check-ignore` 验证 Cookie 备份、历史 JSON、关注/服务配置、头像缓存、INI、日志、SQLite 锁文件及环境文件均被忽略。打包应从干净 CI 检出和专门 staging 目录收集产物，禁止将开发机项目目录、应用用户目录或整个 build 树作为发布包上传。
