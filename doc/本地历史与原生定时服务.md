## 范围与入口

“本地历史”保存 B 站云端观看历史到本地 SQLite。原 `migrate-local-records-ui` 中的“待播队列/播放窗口关闭时归档 JSON”已按本次要求从该 change 执行范围替换掉；旧主规格中的待播能力不能因此视为实现，也没有新增一个同名“本地记录”导航项。

- 主体沿用在线历史的 300px 卡片、16px 间距、居中最短列瀑布流；本地按最近观看时间倒序，每页 30 条，标题栏搜索仅筛选当前页。
- 点击“同步”执行一次完整历史爬取；支持取消。右上角刷新仅重读本地库，不访问历史接口；离页返回也重读当前页，可看到定时任务的新数据。
- “服务管理”先查询系统状态。未注册时先解释并确认注册；取消不改变系统。已注册或注册成功后打开独立管理窗口。
- 管理窗口提供注册/启用/暂停状态、HH:mm、每天/每周（星期一至日）、保存计划、刷新状态/最近运行、暂停/启用与二次确认注销。默认每天 01:00。操作在后台执行，处理中禁用冲突按钮。
- 中英翻译、FluentUI 主题与 Qt 逻辑尺寸已接入。窗口无需通过外部脚本或独立桌面入口打开。

## 爬虫与数据保留

爬虫完全使用 C++/Qt：`HistoryApi` → `HistorySyncRunner` → `HistoryStore`。参考 API 文档 `docs/historytoview/history.md`，访问 `/x/web-interface/history/cursor`，使用 `ps=30&type=all`，逐页传回响应的 `max/view_at/business`；请求显式直连，读取现有 Cookie 文件，不复制 Cookie 到计划任务。

一页落库后至少等待 1 秒再请求下一页；等待支持取消。无 data/空 list 正常结束。非空页缺有效游标、重复或跨多页循环游标会明确停止并报错；登录失效、网络错误不循环重试。云端接口只返回可见历史，无法从接口补回此前未采集且已超出云端范围的观看。

- `videos` 每个 `business:oid:kid` 一行；`view_records` 每个 `(video_key, view_at)` 一行。
- 新的真实观看时间追加一个事件；重复抓到同一时间戳计为“已存在”，不覆盖原事件的时间、进度或原始数据，不把同步执行时间当作播放时间。
- 卡片显示“已记录 · N 次”，单次也显示；悬停列出每次观看时间及当时进度。共享卡片的其他页面保持原有默认显示。
- 较旧页不能覆盖最近观看的标题、作者、封面或进度；云端不再返回的历史仍留在本地。
- 同库 `QLockFile` 阻止手动与定时任务重叠爬取；SQLite WAL、busy timeout 和页事务保留。失败页全部回滚，已提交页保留。
- 修复可选字符串为 SQL NULL 时导致 NOT NULL 失败的问题，关闭并移除线程所属 SQL 连接，避免长时间同步积累连接；观看事件按当前视频批次查询，兼顾本地分页和大库导出。
- 同步审计记录 manual/scheduled 来源、起止、页数、读取、新增、已存在和成功/失败/取消状态；成功后通过 `QSaveFile` 原子更新 JSON 导出。
- 初始化、读取、写入失败均回到界面报告；读取失败保留已有卡片/计数，目录权限修复后可以重试。快速翻页的旧响应不能覆盖新页。

## 两平台定时机制

| 平台 | 系统机制 | 执行身份与运行条件 | 休眠/关机 |
| --- | --- | --- | --- |
| macOS | 当前用户 LaunchAgent，`StartCalendarInterval` | 当前登录用户；关闭应用主窗口仍可触发 | launchd 可能在休眠唤醒时合并执行一次；关机/注销期间不执行 |
| Windows | Task Scheduler，日/周 CalendarTrigger | 当前用户 `InteractiveToken`、`LeastPrivilege`；用户需保持登录 | `StartWhenAvailable=false`、`WakeToRun=false`；错过计划不补跑、不主动唤醒 |

默认不注册 SYSTEM 服务，不要求 root/管理员，也不主动弹 UAC。企业策略、TCC、系统禁止后台任务或文件权限拒绝会报告错误，不绕过权限限制。macOS 的应用/凭据位于受保护目录时，后台进程可能需要用户在系统设置授权相应访问。

配置文件为应用数据目录内 `history-service.json`，仅包含程序、Cookie、数据库、导出的绝对路径以及周期/时间/启用设置。任务名称为 `com.bbhouse.history.<hash>`，按当前用户与配置路径隔离；macOS 对应 plist 在当前用户 `~/Library/LaunchAgents`，Windows 使用同名计划任务。移动程序或 Cookie 后，在新位置启动程序并重新保存计划，以更新固定路径。

注册/更新使用原子配置、结构化 XML/plist 和 QProcess 参数数组；含空格、中文和 XML 特殊字符的路径不经过 shell。查询失败与未注册区分；修改失败尝试恢复旧配置/任务，回滚失败会明确要求刷新核对实际状态。系统最后一次非零执行结果也会显示，便于诊断尚未进入程序/尚未写入数据库就失败的后台任务。

注销需要用户在管理窗口确认；只移除计划任务/LaunchAgent，保留 SQLite、导出和计划配置。手动同步仍可使用。暂停阻止后续计划；macOS 重新加载/移除任务时可能中断正在运行的服务进程，程序收到 SIGTERM 会在当前请求结束后按取消收尾。

## 无头入口

系统调度器执行同一程序：

```text
bbhouse-qt --history-sync-once --config <history-service.json 的绝对路径>
```

入口在 QApplication、QML、mpv 和页面控制器初始化之前分流，只创建 QCoreApplication；不按当前工作目录重新寻找 Cookie 或默认数据库。退出码：0 成功/禁用计划跳过，2 参数或配置无效，3 同步失败或任务冲突，4 收到取消。正常进入数据库的失败会写 scheduled 审计；程序无法启动或数据库不可写时，可从系统执行结果判断失败。

## 手测清单

1. 打开本地历史并同步，确认进度每页推进，首次保存成功。无新观看时再次同步，新增应为 0；再次观看同一视频并等待云端更新后同步，卡片只一张、次数增加，悬停仍能看到旧时间/进度。
2. 滚动、封面预览、视频主体播放、作者空间及返回保持既有行为；分页、页内搜索、刷新与服务新增数据后的重入正常。断网/无效 Cookie 时已有卡片不丢失。
3. 首次点击服务管理，取消注册提示不会创建任务；确认后打开独立窗口。再次打开应直接进入，状态和计划一致。
4. 分别在 macOS/Windows 设置几分钟后的时间；检查每天/每周星期选项，保存后关闭主应用、保持登录，等待系统触发。重开查看 scheduled 日志及本地新增内容。
5. 暂停、启用并重开管理窗口，状态与系统调度器一致。尝试非法 HH:mm，不能覆盖旧计划；模拟权限拒绝/失效路径，错误明确而非假报成功。
6. 注销先取消，再确认；确认后任务移除，本地历史与配置仍在，手动同步正常，再注册可恢复此前周期/时间。
7. 中英、明暗、最小窗口与高 DPI 下检查独立窗口的表单/错误/日志滚动。macOS 另检查后台访问 Documents/凭据文件的权限；Windows 检查非管理员任务注册与企业策略限制反馈。
